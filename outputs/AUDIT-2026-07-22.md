# AgentSkin 完整项目病例（严格只读审计）

> 审计日期：2026-07-22 ｜ 范围：`src/`、`scripts/`、`docs/`、`*.config.ts`、`forge.config.ts`、`electron-builder.yml`、`assets/`、`themes/`、`README*.md`、`.github/`
> 方法：4 路并行深度只读审计 + 关键发现逐项直接核验（grep / Read）。**未对任何文件做任何修改。**
> 结论基调：核心架构约束基本成立；问题集中在 **构建阻断、文档与代码严重不符、孤立/空桩模块、少量逻辑 bug 与冗余**。

## 0. 一句话结论

项目**架构主干健康**，但存在 **2 个会让 CI 直接挂掉的构建阻断**、**1 处文档虚构功能（OAuth/收藏/发布）与代码零实现矛盾**，以及若干 HIGH/中危的逻辑与冗余问题。另外，项目自带的 `working_memory` 与当前代码已严重脱节（仍描述已不存在的 `useDashboard`/`Dashboard` 页面），需要重写。

## 1. 阻断级 / 严重（必须修，否则构建或交付失败）

### 🔴 B1. `sharp` 在 package.json 声明但不在 lockfile —— `npm ci` 必失败
- 位置：`package.json:29`（`"sharp": "^0.35.3"` in `dependencies`） vs `package-lock.json`（无 `node_modules/sharp` 任何条目，已直接核验：grep 0 命中）。
- 影响：`.github/workflows/build.yml` 三处使用 `npm ci`（安装阶段）。lockfile 与 package.json 不一致，`npm ci` 直接报错退出，**macOS/Windows CI 安装阶段即整体失败**。
- 修复：`npm install` 重新生成 lockfile；并把 `sharp` 移入 `devDependencies`（见 M6）。

### 🔴 B2. CI 校验 `*-Portable.exe`，但 electron-builder 只产出 NSIS Setup
- 位置：`electron-builder.yml:10-11`（`win.target: [nsis]`） vs `.github/workflows/build.yml:207,220-221`（注释与校验要求生成 `*-Portable.exe`，否则 `throw 'The Portable executable was not generated.'`）。
- 影响：Windows CI 的验证步骤必然失败。
- 修复二选一：在 `electron-builder.yml` 的 `win.target` 增加 `portable`；或删掉 `build.yml:220-221` 的 portable 校验。

### 🔴 B3. README 描述的功能在代码中完全不存在（文档欺诈级）
- 位置：`README.md:23,33,47-49`。声称 **AgentSkin 账号登录（OAuth 2.0 PKCE）**、**Favorites 收藏**、**发布/分享**、**profile 编辑**、**Authorized apps 页面**、凭据以 0600 存储。
- 核验：全仓 grep `OAuth|登录|Favorites|收藏|publish|分享|sign-in|account` 在 `src/`、`preload.ts`、i18n 中 **0 实现命中**；`electron-builder.yml:42` 为 `publish: null`。
- 影响：对外文档严重误导用户/贡献者；且与"去登录、去 Codex 品牌"的既有重构方向矛盾（见 §6）。
- 附带：README.md:49 本身还有一处乱码（`data directory �� the same model`），是编码损坏。
- 修复：要么实现这些功能，要么把 README 改为与现状一致（推荐后者，与 Phase 1 去登录方向一致）。

## 2. 高危（High）

### 🟠 H1. `useEnvironments` 绕过 EnvironmentStore，读原始 localStorage（与其 JSDoc 自相矛盾）
- 位置：`src/ui/hooks/useEnvironments.ts:39` 引入了 `loadPresets`，但第 70-80 行 `useMemo` 实际读 `window.localStorage.getItem('agentskin:environment-presets')`。`loadPresets` 是死导入。
- 影响：`src/ui/hooks/useEnvironments.ts:17` 的 JSDoc 明写"Presets are loaded via EnvironmentStore (not raw localStorage)"，代码直接违反。任何未来的 EnvironmentStore 逻辑（迁移/加密/默认种子）会被静默跳过。
- 修复：改走 `loadPresets()`，删除死导入与矛盾注释。

### 🟠 H2. `useAgents` 无 loading 态 → 首页误闪"空环境"空状态
- 位置：`src/ui/hooks/useAgents.ts:14-19`（`agents` 初始 `[]`，无 `loading` 标志）。`useEnvironments` 由 `agents` 派生 `environments`，首次渲染 `environments.length===0` → `EnvironmentGrid` 渲染"no environments"空态，直到 catalog 解析。
- 影响：每次启动短暂显示误导性空状态。
- 修复：增加 `loading` 标志并据此门控空状态。

### 🟠 H3. 安装向导的状态机从未被真正驱动（进度是假的）
- 位置：`src/ui/hooks/useThemeInstallFlow.ts:165`（`runImport`）与 `:134`（`retryInstall`）：文件对话框一 resolve 就 `markAllDone()`。
- 影响：精心设计的 `select→read→validate→copy→register→cache→done` 状态机永远瞬间跳到 done；`InstallWizard` 没有真实进度。文件自身注释"Real step-by-step progress (no fake random progress)"是误导。
- 修复：要么用真实 IPC 子事件驱动步骤，要么简化为 loading Spinner 并删掉误导注释。

### 🟠 H4. 实验性适配器已注册且会抛错，但 UI 是否屏蔽"应用"未确认（风险）
- 位置：`src/adapters/*`（codebuddy/marscode/comate/tongyi_lingma/tencent_ai_code）`apply/restore/detect` 抛 `AGENTSKIN_EXPERIMENTAL_ADAPTER`（`base.ts:154-157`）。
- 影响：若 UI 对这些 agent 暴露"应用主题"入口，用户会得到硬错误。需确认 UI 已用 `supported:false`/实验标签隐藏应用动作（审计中未见明确守卫，列为风险）。
- 修复：在 UI 层对 experimental 显式禁用 apply 或标注"实验性不可用"。
