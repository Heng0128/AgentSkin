# AgentSkin 前端信息架构与 UI 重构方案评审

> 版本：草案 v1
> 日期：2026-08-09
> 范围：Dashboard / Workspace / Themes / Wallpaper / Settings / ThemeStudio 六大页面 + 共享组件
> 目标：解决前两轮评审暴露的「信息架构混乱」与「设计细节不合理」问题，给出备选方案并评选最优，兼顾长期演进

---

## 一、问题总汇（两轮评审合并）

### A. 整体信息架构层（最根本）

| # | 问题 | 影响 |
|---|------|------|
| A1 | **Agent 实体信息散落三处**：Dashboard 看状态、Workspace 看环境绑定、Settings 看路径/端口覆盖 | 用户无法判断「Agent 相关信息到底在哪个页面」 |
| A2 | **Dashboard 与 Workspace 职责重叠**：Dashboard 是 Workspace 的「缩略摘要」，信息重复但都不完整 | 双入口，用户不知道该看哪个 |
| A3 | **Dashboard 无时间维度**：全是当前静态快照，无「最近活动/趋势」，本质是状态页 | 仪表盘名不副实 |
| A4 | **Settings 分区维度混乱**：General/Apps/System/Diagnostics 是三种不同维度混排 | 心智模型混乱 |
| A5 | **主导航名称不一致**：菜单「工作室」/页面「工作区 Workspace」/Dashboard 标题「AgentSkin Overview」 | 命名混淆 |

### B. 设计细节层

| # | 问题 |
|---|------|
| B1 | 快捷键冲突：⌘W/⌘I 在 Workspace 与 CommandPalette 指向不同命令 |
| B2 | 两套设计语言并存（（历史）Swiss 克制 vs EnvironmentHero 炫酷玻璃拟态） |
| B3 | 色彩原则冲突：宣称「仅红强调」，但语义色（绿/黄/灰）+ 红色被滥用 |
| B4 | 动效两极分化（环境区堆满动画 vs 工具面板无动画） |
| B5 | 信息密度过载：StatusBar 8 段信息、RenderSettings 15+ 滑块、ThemeCard 徽章墙 |
| B6 | 9px 等宽表格字体不可读 |
| B7 | 无障碍薄弱（自定义组件无键盘导航/ARIA） |
| B8 | 缩写/单字符图标无 tooltip（V/S/T、LOCAL、SW） |
| B9 | 统计卡不可点、禁用按钮无原因、新建入口隐藏 |
| B10 | Custom CSS 放 General 最显眼、System 空分区、Diagnostics 混入常规设置、无设置搜索、无重置 |
| B11 | Theme Studio 复杂度超标（BETA）、ErrorBoundary 全屏、i18n 不完整 |

## 二、三个备选方案

### 方案 A：实体聚焦 / 三视图收敛（中等改动）

**核心思路**：围绕两大核心实体「Agent」和「Theme（含 Wallpaper）」组织产品，每个实体只在一个页面有主视图，其余页面做引用与跳转。

**页面职责重定义**

```
┌─────────────────────────────────────────────────────────────────────┐
│  AgentSkin 主导航（方案 A）                                          │
│                                                                     │
│  ┌──────────┐  Agent 是核心实体，独立成「Agents」中心视图            │
│  │ 概览      │  ← 原 Dashboard 转型：最近活动时间线 + 环境快捷入口    │
│  │           │     + 统计趋势（环比），不再是纯静态快照               │
│  ├──────────┤                                                        │
│  │ 环境      │  ← 原 Workspace 回归：环境 CRUD 主视图                │
│  │           │    （环境 = Agent 组 + 主题 + 壁纸 的组合）            │
│  ├──────────┤                                                        │
│  │ Agents    │  ◀ NEW：聚合所有 Agent 的管理视图                      │
│  │           │    状态 / 路径与端口覆盖 / 版本 / 运行列表             │
│  │           │    （吸收原 Dashboard 的 Connected Agents             │
│  │           │     + Settings 的 Apps + Workspace 的 Agent 状态）    │
│  ├──────────┤                                                        │
│  │ 主题      │  ← 原 Themes，保持                                    │
│  ├──────────┤                                                        │
│  │ 壁纸      │  ← 原 Wallpaper，保持                                  │
│  ├──────────┤                                                        │
│  │ 设置      │  ← 只含应用级配置：General / 外观 / 关于               │
│  │           │    诊断与开发者项收进「高级」分区                      │
│  └──────────┘                                                        │
└─────────────────────────────────────────────────────────────────────┘
```

**要点**：
1. **Agent 归一处**：新建 Agents 视图，彻底解决 A1。
2. **Dashboard 转型**：有「最近活动」时间线 + 环境快捷入口 + 统计趋势（A3）。
3. **Environment 成为一等实体**：环境卡片聚焦「封面 + 名称 + 最近编辑 + 主操作」，去掉 Agent 状态（A2、B5）。
4. **Settings 重分区**：General/外观/关于 为主，Diagnostics 收进「高级」，Custom CSS 移出 General（B10）。
5. **命名统一**：导航、页面标题、路由、功能四方一致（A5）。

**改动量**：中等。新增 1 个页面，重排 3 个页面，需要数据模型层把 Agent 状态从环境/设置中抽离。

---

### 方案 B：多视图 + 二级导航（小改动，Hub-and-Spoke）

**核心思路**：保留现有 6 页结构，用「概览 Hub + 页内二级导航」收敛碎片信息，最小化改动。

**页面职责重定义**

```
Dashboard = Hub（概览中心）
  ├── 最近活动时间线
  ├── 各模块入口卡（环境/主题/壁纸）
  ├── 统计与趋势
  └── Agent 状态（保留，但只做摘要，详细跳转）

Workspace = 环境管理（页内用 Tabs 组织子视图）
  ├── Tab: 所有环境
  ├── Tab: 已绑定 Agent
  └── Tab: 快捷操作

Settings = 重分区（改维度）
  ├── General（含外观，去掉 Custom CSS）
  ├── Apps（保留，Agent 路径/端口）
  ├── System（补全内容）
  └── 高级（Diagnostics + Custom CSS 收进来）
```

**要点**：
1. Agent 信息**仍分散**，但通过「摘要 + 跳转」收敛，避免重复展示（A1 部分缓解）。
2. Dashboard 成为 Hub，有入口和趋势（A3）。
3. Settings 用 Tabs/分区统一维度（A4）。
4. 侧边栏保持 6 项，改动小。

**改动量**：小到中。无需新增页面，主要是 Dashboard 增强 + Settings 重分区 + 页内导航。

---

### 方案 C：激进收敛 / 环境优先（大改动）

**核心思路**：砍掉独立 Dashboard，产品围绕唯一核心实体「环境」组织，Agent 只是环境的一个属性。

**页面职责重定义**

```
主导航（4 项）
  ├── 环境（Workspace 扩展为首页，含概览片段 + 全部环境 CRUD）
  ├── 主题
  ├── 壁纸
  └── 设置（General/外观/关于 + 高级）

Agent 管理：不设独立页面
  └── 作为「环境详情」内的一个区域，或「设置→高级」的子项
```

**要点**：
1. 最简导航，Dashboard 功能并入 Workspace 首页（A2 彻底解决）。
2. Agent 独立管理被弱化，适合「Agent 数量少、型号固定」的场景。
3. 改动大，信息架构彻底重构。

**改动量**：大。删除页面 + 全部数据流重接。

## 三、横向评分对比

评分维度（1-5 分，5 最优）：

| 维度 | 权重 | 方案 A | 方案 B | 方案 C |
|------|------|:------:|:------:|:------:|
| 解决 Agent 信息分散（A1） | 高 | 5 | 3 | 2 |
| Dashboard/Workspace 边界（A2） | 高 | 5 | 3 | 5 |
| 可扩展性（Agent/主题生态扩张） | 高 | 5 | 3 | 2 |
| Settings 合理性（A4） | 中 | 5 | 4 | 4 |
| 命名一致性（A5） | 中 | 5 | 3 | 4 |
| 理解成本（对用户） | 中 | 4 | 3 | 5 |
| 改动成本（对团队） | 中 | 3 | 4 | 2 |
| 设计一致性落地（B2/B3/B4） | 高 | 4 | 3 | 3 |
| 长期运维（a11y/token/i18n） | 中 | 4 | 3 | 3 |
| **加权总分** | — | **4.4** | **3.3** | **3.1** |

**前置条件自省**：
- 方案 A 的 5 分建立在「Agent 确实是核心实体、且 Agent 型号会持续增加」这个判断上。从当前产品（TRAE/Qoder/WorkBuddy/ZCode/Codex + Settings 已为每个 Agent 留路径/端口覆盖）看，这个判断成立。
- 若 Agent 型号固定、极少新增，则方案 A 的「Agent 独立视图」价值下降，方案 C 更省。

## 四、最优方案：方案 A（实体聚焦）

**推荐理由**：
1. **根治 A1**：Agent 独立成视图，一次解决「状态/绑定/配置三处分」的根本矛盾，这是两轮评审里最核心的问题。
2. **每个页面单一职责**：概览=时间线、环境=CRUD、Agents=管理、设置=配置，符合「一个实体一个主视图」的成熟产品原则（Linear/Notion 均如此），心智模型清晰。
3. **可扩展性强**：Agent 生态会扩张（新增型号、路径、端口、版本、更新的管理都要落位），独立视图为后续扩展留了明确空间——这是「考虑长远」的关键。
4. **Dashboard 回归本质**：从「静态状态页」变成「最近活动 + 趋势 + 快捷入口」，才是真正的仪表盘。
5. **Settings 干净**：App 级配置独立后，设置页只剩 General/外观/关于 + 高级，分区维度统一。

**方案 A 的落地切分（控制改动风险）**：

```
阶段 1（信息架构骨架）  —— 先立结构，后打磨
  ├ 新建 Agents 视图，从 Dashboard/Workspace/Settings 抽离 Agent 数据
  ├ Dashboard 转型为「概览」（最近活动 + 入口 + 趋势）
  ├ Settings 重分区（General/外观/关于 + 高级；Custom CSS 移入高级）
  └ 命名统一（导航/标题/路由/功能一致）

阶段 2（细节一致性）    —— 前两轮 B 类问题打包处理
  ├ 修复快捷键冲突（⌘W/⌘I 全局注册表 + 冲突检测）
  ├ 统一设计语言：收敛 EnvironmentHero 玻璃拟态，对齐项目 token
  ├ 语义色与品牌色分离，红色收敛为关键动作专属
  ├ 信息密度：StatusBar 精简 / RenderSettings 分级 / ThemeCard 减徽章
  ├ 9px 字号提升至 11px+，缩写图标加 tooltip
  └ 统计卡可点、禁用按钮加原因 tooltip、新建入口统一为主 CTA

阶段 3（长期演进）      —— 可扩展性支撑
  ├ 建立设计系统 Token 文档（颜色/间距/字号/圆角，含暗色）
  ├ 无障碍：自定义组件补键盘导航 + ARIA，发布前 a11y 检查
  ├ 局部 ErrorBoundary（只降级出错区块，不全屏）
  ├ i18n 补全（消除硬编码中文），支持中英双语
  └ 数据口径统一（Agent 状态由 Agents 视图单一事实源，其他页面只引用）
```

## 六、长期演进路线图（方案 A 之上）

| 时间 | 里程碑 | 内容 |
|------|--------|------|
| 近期 | 信息架构落地 | 阶段 1：Agents 视图 + Dashboard 转型 + Settings 重分区 + 命名统一 |
| 近期 | 细节一致性 | 阶段 2：快捷键 / 设计语言统一 / 色彩分离 / 信息密度 / 字号 / tooltip |
| 中期 | 设计系统化 | 阶段 3：Token 文档、组件库文档与 Storybook、暗色模式完善 |
| 中期 | 无障碍与国际化 | 键盘导航 + ARIA + a11y 检查、i18n 双语 |
| 长期 | 生态可扩展 | Agent 插件化（新型号接入）、主题市场/分享、多平台（macOS 已预留） |

**长期风险提示**：
1. 若未来 Agent 型号数量激增，Agents 视图需支持**搜索/分组/批量操作**，阶段 1 就应预留列表结构而非单卡。
2. 设计一致性是「长期债」：宁可阶段 1 就定死 token 与组件规范，避免 9px/mono、玻璃拟态这类临时风格固化进代码库。
3. 无障碍与 i18n 越晚补越贵，建议随阶段 2 一并做，而非留到「有时间再说」。

## 七、结论

**推荐采用方案 A（实体聚焦）**，并按「先结构、后细节、再演进」三阶段落地。它从根上解决 Agent 信息分散的矛盾，让每个页面单一职责，同时为 Agent/主题生态的长期扩张预留了明确空间。阶段 1 的骨架应在设计 token 与组件规范锁定前完成，避免风格碎片固化。

*如团队倾向低风险快速上，可退化为方案 B 先做 Dashboard 增强 + Settings 重分区，后续再向方案 A 收敛。*
