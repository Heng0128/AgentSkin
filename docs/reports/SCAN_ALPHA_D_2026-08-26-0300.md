## 1. 扫描方法

对 src/ 目录下全部 .ts/.tsx 源码（排除 test 文件、node_modules）执行以下模式匹配：

1. `if (success) { ... }` 无 else / `catch(() => {})` 空吞错 / Promise 无 .catch
2. 异步操作前无 `setLoading(true)` / 无 Spinner 组件
3. `map` 渲染列表前无空数组 guard / 无 EmptyState
4. 无输入校验 / 无长度上限 / 无 null/undefined guard
5. 按钮在 `.loading` 时未加 `disabled`
6. fetch / IPC 调用无超时配置
7. 无 loading guard 防止重复点击（并发守卫）

## 4. 根因聚类

### 4.1 错误吞噬 / 静默失败 (7 例: alpha-3, alpha-4, alpha-5, alpha-6, alpha-9, alpha-10, alpha-20)

**分布**: stores (themeStore, workspaceStore, wallpaperStore), components (detailPanel, CommandPalette, PerformancePanel, AgentDetailSheet), main process (agent-engine-service)

**根因**: 
- 异步操作的 `.catch()` 仅 `console.warn` 或完全吞错（`() => undefined`）
- store action 返回 `false`/失败后 UI 层不消费该返回值
- 统一的 error propagation 机制缺失——错误未从 store action 传到 UI 层

**建议**: 
1. 所有 store 异步 action 失败时 dispatch notification.fail() 或设置 error state
2. UI 层消费 action 返回值，失败时展示 inline error / retry
3. main process 的 `.catch(() => undefined)` 至少加 `logStructured`

### 4.2 并发守卫缺失 (6 例: alpha-2, alpha-8, alpha-12, alpha-16, alpha-17, alpha-20)

**分布**: stores (statusStore, wallpaperStore, themeStore), components (AgentLivePreview, SettingsPage), main process (agent-engine-service)

**根因**:
- `useEffect` 依赖对象引用导致无限循环（alpha-2）
- 关键操作无 debounce / 去重 token（alpha-8）
- `isRefreshing` 检查缺失（alpha-12）
- module-level Set 无 cleanup 路径（alpha-16）
- `Promise.all` 全并发无 concurrency limit（alpha-17, alpha-20）

**建议**:
1. effect 内使用 request token + 检查缓存引用不变性
2. 对刷新类操作统一加 `isXxxLoading` 守卫 + AbortController
3. module-level busy Set 加 try/finally cleanup
