## 二、候选方案集合（4 套）

### 方案 A：渐进修复（Incremental Fix）

**核心理念**：保留骨架，清创修复。

**改动内容**：
1. 删除 1500 行死代码
2. 修复 5 个 P0 虚假按钮
3. 补充 19 个 i18n key
4. 集成 CenterTabDesignLanguage 到导航
5. 合并 computeSignature 冗余实现

**改动规模**：小
**对标项目**：无特对标，仅内部清理

---

### 方案 B：三栏工作台（Three-Column Workspace）

**核心理念**：借鉴 Tokens Studio + Penpot 三栏布局。

**改动内容**：
1. **左栏**：Token 分类树（Brand / Surface / Text / Border / State）
2. **中栏**：实时预览（6 个 Adapter 同步预览 iframe）
3. **右栏**：属性检查器（HSL 滑块 + Hex 输入 + 对比度实时指示）
4. 移除底部 Dock（功能并入右栏）
5. 清除死代码 + 修复虚假按钮

**改动规模**：中-大
**对标项目**：Tokens Studio（三栏布局 + Token 引用）、Penpot（MCP 接入预留）

---

### 方案 C：实时工作室（Realtime Studio）

**核心理念**：借鉴 Realtime Colors + Coolors，"永远在真实 UI 上预览 + 锁/打乱工作流"。

**改动内容**：
1. **70% 视口**：真实 Adapter 预览（非 mockup，而是真实注入后的 DOM 截图）
2. **底部工具栏**：可锁定的色块行 + Shuffle 按钮
3. **交互**：点击色块 → OKLCH 色区拾色器弹出 → 实时预览
4. **对比度指示**：每个色块旁的红/黄/绿灯（WCAG AA/AAA）
5. **锁/打乱工作流**：锁定喜欢的 token → 打乱其余 → 迭代优化
6. 清除死代码 + 修复虚假按钮

**改动规模**：中-大
**对标项目**：Realtime Colors（Distribution 思维）、Coolors（Spacebar shuffle + Lock）

---

### 方案 D：完整工作室（Full Studio）

**核心理念**："Distribution > Isolation + Contrast-first > Color-first + Reference > Duplicate"——真正的工作室级体验。

**改动内容**：

#### D.1 数据层重构
- **14-token 契约升级为 Token 引用系统**（`{colors.primary}` → `{brand.blue}`）
- **DTCG 格式兼容**（与 Tokens Studio 互操作）
- **OKLCH 为内部色彩空间**（感知均匀，编辑更直觉）
- **Adobe Leonardo npm 集成**（`@adobe/leonardo-contrast-colors` 直接接入）

#### D.2 视觉层重构
- **永远可见的真实预览**（Distribution 思维，70%+ 视口）
- **6 Adapter 同步预览**（借鉴 Realtime Colors 多端模式）
- **锁/打乱/和谐规则**（Coolors + Adobe Color 模式）
- **实时 WCAG 对比度矩阵**（Colorable 式红绿标记）
- **色盲模拟视图**（Protanopia / Deuteranopia / Tritanopia）

#### D.3 交互层重构
- **可视化 Token 树**（左侧，Pattern L）
- **属性检查器**（右侧，OKLCH 滑块 + Hex + Contrast）
- **意图级编辑**（"我要 AA 级蓝色主题" → Leonardo 自动推导完整 palette）
- **快照 + 对比**（Pattern I，Before | After 并排）

#### D.4 生态预留
- **MCP 协议接入**（借鉴 Penpot，允许 Claude Code 直接操作主题）
- **DTCG 导入/导出**（与 Tokens Studio 生态打通）

**改动规模**：大
**对标项目**：
- **Realtime Colors**（Distribution 思维 + 70% 预览 + 对比度交通灯）
- **Coolors**（锁/打乱工作流）
- **Adobe Leonardo**（contrast-first 生成 + 自适应联动 + npm 直装）
- **Tokens Studio**（Token 引用 + DTCG 格式 + 多主题切换）
- **Colorable**（实时对比度矩阵）
- **Penpot**（MCP 协议 + AI Agent 接入预留）

## 四、交叉质询结论

### 4.1 为何 D > C？

方案 D 比方案 C 多出的价值：

| D 独有能力 | 收益 |
|-----------|------|
| Token 引用系统 | 修改蓝色 → 所有引用蓝色的 token 自动更新 |
| DTCG 格式兼容 | 与 Tokens Studio 生态打通，可导入/导出专业主题 |
| Adobe Leonardo 集成 | "对比度优先"生成——用户输入意图，算法推导完整 palette |
| OKLCH 色彩空间 | 感知均匀，编辑更直觉，不偏色 |
| MCP 协议预留 | 允许 Claude Code 直接创建/修改主题 |

**差距核心**：方案 C 是"更好的编辑器"，方案 D 是"真正的工作室"。D 实现了从"逐字段编辑"到"意图级编辑"的范式跃迁。

### 4.2 为何 C > B？

方案 C 的"Distribution 思维"（永远在真实 UI 上预览）比方案 B 的"Token 树 + 表单"更贴近用户心智模型。用户不想看到抽象的 token 列表，想看到"我的主题在真实 App 上是什么样子"。

### 4.3 为何不推荐 A？

方案 A 本质上是"修 bug"，不是"建设工作室"。它无法回答"如何让 Studio 变成真正的主题设计工作室"。业务根治仅 5 分，长期演进仅 3 分。

### 4.4 D 的风险为何不可怕？

方案 D 故障安全得 7 分（不是最低），因为：
- Token 引用系统可增量引入（先支持直接值，再加引用语法）
- OKLCH 可在色彩编辑器内部使用，不影响现有 HEX 存储
- Leonardo 是可选增强，不阻塞主流程
- MCP 是预留接口，不影响现有功能

## 五、最终推荐：方案 D — 完整工作室

### 5.1 核心定位

**从"带预览的编辑器"进化为"AI Agent 主题设计工作室"。**

### 5.2 核心能力清单

#### 能力 1：Distribution 预览（P0）
- 70%+ 视口永远展示真实 Adapter 上的主题效果
- 6 Adapter 同步预览（借鉴 Realtime Colors）
- 编辑 token → 预览即时更新（<50ms）

对标：Realtime Colors（300K+ 用户验证的模式）

#### 能力 2：对比度优先生成（P0）
- 集成 `@adobe/leonardo-contrast-colors`
- 用户输入"AA 级蓝色主题" → 自动推导完整 14-token palette
- 自适应主题联动：调亮度 → 全部 token 按感知规则联动

对标：Adobe Leonardo（npm 可直装，WCAG 2.x + APCA 双标准）

#### 能力 3：锁/打乱工作流（P0）
- 底部工具栏显示所有 token 色块
- 锁定喜欢的 → 打乱其余 → 迭代优化
- 借鉴 Coolors Spacebar 交互

对标：Coolors（12M+ 用户使用验证的模式）

#### 能力 4：实时对比度矩阵（P1）
- 编辑时即标红不合规组合
- 色盲模拟视图（3 种视图切换）
- 14-token 中关键配对的二维矩阵

对标：Colorable（jxnblk 开源，纯函数可集成）

#### 能力 5：Token 引用系统（P1）
- `{colors.primary}` → `{brand.blue}` 语义别名
- 修改一处 → 所有引用处自动更新
- DTCG JSON 存储（与 Tokens Studio 兼容）

对标：Tokens Studio（W3C DTCG 标准贡献者，MIT 开源）

#### 能力 6：意图级编辑（P2）
- "我要一个冷色调 + AA 对比度 + 紧凑布局"
- Leonardo 算法推导完整配置（color + spacing + radius + shadow）

#### 能力 7：MCP 协议预留（P3）
- 允许 Claude Code / Cursor 直接操作主题
- 为 AI Agent 协作埋入口

对标：Penpot（2024 年接入 MCP，54K stars）

### 5.3 执行波次（仅规划，不落地）

1. Distribution 预览（70% 视口真实 Adapter 预览）
