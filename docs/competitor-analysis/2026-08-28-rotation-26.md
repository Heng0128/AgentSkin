## 🔍 深度分析

### 1. CodeDrobe/core — 最强直接竞品

**仓库元数据**
- License: Apache-2.0
- 创建: 2026-07-16
- 最后推送: 2026-07-21 (v0.7.0-beta.0)
- Topics: `ai-coding`, `chrome-devtools-protocol`, `cli`, `codex`, `electron`, `nodejs`, `openai-codex`, `qcoderwork`, `theming`, `trae`, `workbuddy`
- 内置适配器: `codex`, `workbuddy`, `qoderwork`, `traework`

**架构分析**

CodeDrobe 采用与 AgentSkin 几乎同构的分层设计：

```
CLI (codedrobe) → Core Runtime → Adapter Layer → CDP WebSocket → 目标应用
```

关键设计亮点：

1. **声明式主题包格式 (`.codedrobe-theme`)** — 纯声明式 JSON + CSS + 图片，不含 JavaScript。这与 AgentSkin 的 14-token 契约异曲同工，但更强调"零 JS"安全模型。

2. **DOM 快照 API (`snapshotDom`)** — 只读捕获 DOM 结构 + 计算样式 + 稳定选择器候选 + 边界框 + 适配器 landmark 匹配。排除文本内容、表单值、可访问名称、链接、媒体源。这是为 AI 辅助主题创作提供结构化上下文的绝佳设计。

3. **Landmark 验证系统** — 三级验证：
   - `required`: 必须存在的 DOM 缺失则阻止注入
   - `recommended`: 缺失仅警告
   - `contexts`: 路由特定条件验证（仅在 `when.any` landmark 可见时运行）

4. **Per-window 验证语义** — 次级窗口（弹出聊天、隐藏覆盖层）缺少 `required` landmark 时降级为 `skipped`，仅当零个窗口符合条件时才失败。这解决了多窗口 Electron 应用的注入鲁棒性问题。

5. **图片资源桥接** — 主题包内嵌图片 → Blob URL → CSS 变量 (`--codedrobe-image-<id>`)。`hero` 图片额外别名 `--codedrobe-art` 和 `--dream-art`（兼容旧格式）。

6. **QoderWork 调试端口发现** — QoderWork 强制 `remote-debugging-port=0`，CodeDrobe 从 `DevToolsActivePort` 文件读取实际端口。这是重要的工程细节。

7. **Codex 热加载** — 切换 Codex 主题无需重启，仅当应用未以 CDP 调试标志启动时才需要重启。

**与 AgentSkin 对比**

| 维度 | CodeDrobe/core | AgentSkin |
|------|----------------|-----------|
| 适配器覆盖 | codex, workbuddy, qoderwork, traework (4) | traework, qoderwork, workbuddy, doubao, codex, zcode (6) |
| 主题格式 | `.codedrobe-theme` 声明式包 | 14-token 契约 + CSS 变量 |
| 验证 | Landmark 三级 + per-window | 注入前后截图对比 |
| 图片处理 | Blob URL → CSS 变量 | 直接路径引用 |
| 包分发 | npx CLI + 商店发布 | 内置 Theme Library |
| 安全模型 | 零 JS、纯声明式 | Adapter 隔离 + epoch 管理 |

**可借鉴的设计模式**

1. **DOM 快照工具** — 为 AI 辅助主题创作提供结构化上下文
2. **Landmark 验证** — 注入前预检，减少失败回滚
3. **Per-window 降级语义** — 多窗口场景鲁棒性
4. **声明式图片桥接** — Blob URL 隔离，避免路径泄露

## 🎯 行业趋势洞察

### 趋势 1: 声明式主题包成为主流

CodeDrobe 的 `.codedrobe-theme` 格式和 AgentSkin 的 14-token 契约都指向同一方向：**主题包应该是纯声明式的、可验证的、不含可执行代码的**。这比传统的 JS 注入方案更安全、更可审计。

### 趋势 2: 图片驱动主题生成

HeiGeAi/deepseek-harness-skin 的"一张图生成整套配色"和 Finderchangchang/codex-autoskin（第 20 轮分析）的"发一张图给 Codex 它自己给自己换肤"表明，**从参考图自动生成主题**是用户期望的杀手级功能。

### 趋势 3: 多窗口鲁棒性

CodeDrobe 的 per-window 验证语义和 AgentSkin 的 secondaryInjectStore 都指向同一问题：**Electron 多窗口场景下的注入鲁棒性**。行业正在从"注入即成功"演进为"验证每个窗口"。

### 趋势 4: 社区主题生态

WorkBuddy-theme-skill 的 registry.json 同步 + CodeDrobe 的商店发布 + DSH 的皮肤市场表明，**主题正在从个人创作走向社区生态**。

## 🚀 推荐执行方案

### P0: 图片驱动主题生成引擎 (ImageDrivenTheme)

**来源**: HeiGeAi/deepseek-harness-skin 的一张图生成整套配色

**方案**: 在 `scripts/` 中新增 `image-to-theme.mjs` CLI 工具：
- 输入: 图片路径
- 处理: 提取主色 → 保对比度推导 14-token → WCAG 校验
- 输出: 符合 AgentSkin 14-token 契约的主题 manifest

**可行性**: 高 — 已有 color-quantize.ts 和 deriveTokens 基础
**价值**: 高 — 用户期望的杀手级功能

### P1: 注入验证增强 (LandmarkVerifier)

**来源**: CodeDrobe/core 的 landmark 验证系统

**方案**: 在 engines/ 中新增验证层：
- 定义每个适配器的 required/recommended landmarks
- 注入前预检，缺失 required 则阻止
- 注入后验证 CSS 变量是否生效

**可行性**: 高 — 可复用现有 CDP 连接
**价值**: 中高 — 减少注入失败和回滚

### P1: 主题清理清单 (ThemePurgeRegistry)

**来源**: ZhjGo/codex-skin-manager 的 purge-all.mjs

**方案**: 为每个主题定义清理清单：
- CSS 变量名列表
- DOM 选择器列表
- 定时器/监听器标识

**可行性**: 高 — 纯数据结构
**价值**: 中 — 提升主题切换清洁度

### P2: DOM 快照工具 (DomSnapshot)

**来源**: CodeDrobe/core 的 snapshotDom API

**方案**: 新增 CDP 工具函数：
- 只读捕获 DOM 结构 + 计算样式
- 输出 JSON 供 AI 辅助主题创作

**可行性**: 中 — 需要维护选择器稳定性
**价值**: 中 — 为未来 AI 创作提供基础
