### 技术实现亮点

#### 1.1 `.codexskin` 格式 SPEC（SPEC.md v1.1, schemaVersion 2）

包结构：zip 根直接放 `theme.json` + `theme.css` + `chrome.html`（可选）+ `assets/` + `previews/`。安装器按 manifest `id` 放置内容而非按文件夹名——消除重命名导入风险。

工程约束：
- 单素材 ≤ 1.4 MB raw（比 Chromium 2 MB data URL base64 上限留出余量）
- 动效素材 ≤ 24 MB raw，推荐 ≤ 8 MB
- 包 ≤ 50 MB / 500 entries
- 素材上禁止文字/logo

#### 1.2 CSS 作用域策略

所有选择器挂在 `html.codex-theme-studio` 单类名下。运行时注入单条 `<style id="cts-style">`，完全不需要建树与样式隔离层。关闭时单日 class 移除即可还原——符合其"零残留"承诺（VERIFY_REMOVED_EXPRESSION 精确断言 14 类 0 残留）。

#### 1.3 三层变量命名空间

| 前缀 | 来源 | 用途 |
|------|------|------|
| `--cts-color-<key>` | theme.json `colors` | 颜色 token |
| `--cts-str-<key>` | theme.json `strings` | 文案 token |
| `--cts-asset-<key>` | theme.json `assets` | WebP data URL 内联 |
| `--cts-intro-duration` | 运行时 | 开屏动效时长 |

素材经 Python + Pillow alpha 验证管线后，data URL 直接内联到 `:root.codex-theme-studio` 块中——禁 blob URL，避免"晚加载图片 revoke"的时序竞动。

#### 1.4 Stage/Overlay 双装饰层 + chrome.html

两层 HTML 装饰以 `pointer-events: none` 永挡交互：
- `#cts-stage`：背景素材层
- `#cts-intro`：一次性开屏动画
- `#cts-chrome`：自定义 HTML 框架（同心环、装饰徽章等）

#### 1.5 codexTheme 块桥接原生主题

`theme.json` 的 `codexTheme` 块可被 Codex App Manager 写入 `~/.codex/config.toml` 的 `[desktop]` 表：
- `appearanceTheme`（dark/light/system）
- `codeThemeIds`（dark/light 双码主题 ID）
- `light`/`dark` 子块的 accent、contrast、ink、surface、fonts.code/ui、semanticColors
- shareString 往返校验保证 TOML 解析的对称性

### 与 AgentSkin 兼容性分析

| 维度 | AgentSkin | awesome-codex-skins |
|------|-----------|---------------------|
| 应用数 | 6 适配器 | 单适配器（Codex desktop） |
| 注入层 | CDP WebSocket（远端） | loopback CDP（本地 127.0.0.1） |
| 主题契约 | 14-token | schemaVersion 2（colors/strings/assets/codexTheme/motionAssets） |
| 皮肤包格式 | Bundle（themes/<theme-id>/） | `.codexskin` zip |

**关键结论**：awesome-codex-skins 的 `codexTheme` 块是两项目间唯一的结构桥接点。AgentSkin 的 codex 适配器可与 `codexTheme` TOML schema 对话，但目前不覆盖 Codex App Manager 的 catalog 消费协议。

### 可借鉴点优先级

1. **P0 — 素材 data URL 内联策略 + Pillow alpha 门禁**：强制 data URL 内联（禁 blob URL），三管线 Python 脚本实现 alpha 验证
2. **P1 — 独立背景 div + MutationObserver 自愈模式**（参见第 3 节 DouBao-Dream-Skin）
3. **P1 — Runtime.verifyExpression 的结构化断言模式**：返回 `composer / composerOverflow / sidebar / chrome / viewport` 多独立判定字段
4. **P2 — REMOVE_EXPRESSION 的 14 类 0 残留契约 + stamp**

### 技术实现亮点

#### 2.1 RenderPlan 语义渲染计划

将主题数据与渲染策略完全分离。主题包（ThemeDefinition V2）只声明"是什么"（颜色、焦点、明暗），不包含"怎么做"（CSS/选择器/脚本）。

```
ThemeDefinition V2 → RenderPlan → CSS Compiler → CDP 注入
```

- **CompatAdapter**：探测当前 Codex 版本的语义角色能力，生成版本兼容的 RenderPlan
- **页面适配**：为首页、任务页和未知页面生成统一的渲染策略
- **固定布局规则**：品牌图（左上）、装饰（右下）的布局由应用固定控制

#### 2.2 CSS Compiler 受控样式编译

主题包本身不能携带 CSS、选择器或脚本。CSS 由 `src/core/render/` 内的编译器从 RenderPlan 生成，主题作者无法直接编写选择器。

#### 2.3 ThemeDefinition V2 最小结构

```json
{
  "schemaVersion": 2,
  "id": "example-theme",
  "assets": { "hero": "hero.webp" },
  "appearance": "dark",
  "art": {
    "focusX": 0.78, "focusY": 0.46,
    "safeArea": "left",
    "taskPresentation": "ambient"
  },
  "palette": {
    "background": "#181A1F",
    "surface": "#22252D", 
    "accent": "#91D94F",
    "secondary": "#E96BB0",
    "foreground": "#F2F4F7",
    "muted": "#A4ACB8"
  }
}
```

协议硬性约束：
- `id` 只允许小写字母、数字和连字符，最长 64 字符
- 图片限 WebP 格式，单资源 ≤ 8MB，整包 ≤ 16MB
- **禁止**未知字段、任意路径、远程 URL、CSS、选择器、脚本、命令

#### 2.4 实机质量门禁（最突出的工程亮点）

主题应用是一个**完整事务**：

1. 暂装主题到 Codex（通过 CDP）
2. 读取受控计算样式
3. **5 项质量检查**：
   - 组件命中（选择器是否匹配到目标）
   - 对比度（文字可读性 WCAG）
   - 回复表面（不被背景干扰）
   - 输入框（保持可用状态）
   - 横向溢出（无滚动条）
4. 通过 → 提交主题
5. 失败 → **自动回滚到上一主题或恢复原生**

### 与 AgentSkin 兼容性分析

两者在架构哲学上高度一致（主题包被动、引擎控制渲染），但主题格式完全不兼容。AgentSkin 的 14-token 契约更偏 CSS 变量级抽象，Codex Chroma 的 V2 更偏语义级抽象（palette 角色色 + 焦点/安全区几何信息）。

### 可借鉴点优先级

1. **P0 — 运行时质量门禁（实机验证）**：在真实 CDP 注入后读取计算样式验证对比度、溢出、组件命中
2. **P1 — RenderPlan 中间表示层**：目标应用版本变化时只调整"版本能力描述 → RenderPlan"的映射
3. **P1 — 期望状态持久化**：记录"上一份成功主题"，重启/更新后提示"需要重新应用"
4. **P2 — 事务性主题应用三段式：试装 → 验证 → 提交/回滚**

## 3. Ky233666/DouBao-Dream-Skin

### 基本信息

| 指标 | 数据 |
|------|------|
| Stars | 3 |
| 最后更新 | 2026-07-21 |
| 语言 | JavaScript（零 npm 依赖） |
| License | MIT |
| 版本 | 0.5.0（早期阶段） |
| 创建日期 | 2026-07-17 |

### 技术实现亮点

#### 3.1 双端分离架构（Web 扩展 + 桌面 CDP）

- **浏览器扩展版**：标准 Chrome/Edge 扩展（Manifest V3），运行在 `doubao.com`。通过 `content.js` 注入 CSS 变量 + 背景 `<div>`，使用 `MutationObserver` 监听 DOM 变化并在背景层被移除时自动恢复。
- **桌面版**：通过豆包自带的 Chromium 调试接口（CDP），用 Node.js 手写 WebSocket 客户端（无第三方依赖）连接 `127.0.0.1:<port>`。

#### 3.2 智能文字对比度

Auto 模式对背景图进行**低分辨率本地采样**（把背景缩小后逐像素算亮度均值），根据结果分别为 sidebars/surface/composer 三个区域选取深色或浅色文字。全程本机完成，不会上传图片。

#### 3.3 背景层独立 div + MutationObserver 自愈

`<div id="doubao-dream-skin-web-background">` 隔离于 React 渲染树之外，避免被 React 重渲染清掉；`MutationObserver` 随时修复。比直接在 body 上设置 `background-image` 更稳定。

#### 3.4 手写 CDP 的安全校验

`cdp-client.js` 对 WebSocket URL 做了严格白名单：只允许 `127.0.0.1` / `localhost` / `[::1]`，路径必须是 `/devtools/page/<id>` 或 `/devtools/browser/<id>`，拒绝一切非 loopback 或非标准路径的调试目标。

#### 3.5 四套预设主题 + 三档组件风格

| 预设名 | 风格关键词 | 组件风格（soft / outline / solid） |
|--------|-----------|-----------------------------------|
| 暖霞玻璃 | 暖色、人像、柔和圆角 18 | soft |
| 午夜霓虹 | 深色玻璃、青色高光、圆角 20 | solid |
| 樱花梦境 | 粉紫、动漫、圆角 22 | soft |
| 海盐微风 | 蓝绿、清爽、圆角 16 | outline |

### 与 AgentSkin doubao 适配器对比

| 维度 | DouBao-Dream-Skin | AgentSkin doubao 适配器 |
|------|-------------------|------------------------|
| Token 体系 | 27 个 `--dbsw-*` 自定义变量 | 14 个 `--agentskin-*` 契约 + 桥接覆盖 251 个原生 `--dbx-*` 与 `--semi-*` token |
| 双端支持 | Web 扩展 + Windows 桌面 | 仅桌面端 Electron |
| 第三方依赖 | **零依赖**（纯 Node.js 内置模块） | React 19 + Zustand + Electron 完整工程栈 |
| 注入安全 | 手写 WebSocket CDP + URL 白名单 | 运行时 patch（`patchWindowsAdapters`） |

### 14-token 合约映射

| AgentSkin 14-token | DouBao-Dream-Skin 能否覆盖 |
|--------------------|----------------------------|
| accent / surface / border / input-bg | ✅ 直接对应 |
| muted | ⚠️ 分区域双轨 |
| bg | ❌ 无原生等价 |
| code-bg / code-fg | ❌ 完全没有 |
| focus-ring / selection | ❌ 无显式变量 |

### 可借鉴点优先级

1. **P0 — 独立背景 div + MutationObserver 自愈**：豆包切换 `data-theme` 时原生 CSS 会覆盖 body.background，独立 div 方案更稳定
2. **P0 — 选择器脱耦到 CSS 变量层**：主题切换不需要重新选择 DOM，只换变量
3. **P1 — CDP URL 白名单 + multi-source 进程发现**：安全校验模式 + 候选路径扩展
4. **P2 — 本机智能文字对比度采样**：辅助 Studio 自动选择 dark/light mode
5. **P2 — 网页版支持**：AgentSkin 目前不覆盖豆包网页版（需 RFC）

## 4. Trentct/Codex-Skin

> **注**：原始仓库 `Trentct/Codex-Skin` 可能已设置为私有或删除（GitHub API 返回 0 结果）。参考分析基于同领域最相关项目 **Fei-Away/Codex-Dream-Skin**（4,400+ stars）。

### 技术实现亮点（继承自 sdk-beta）

#### 4.1 Foundation + Character 分层架构

- **Foundation 层**：声明式语义基础（颜色语义、排版、间距），独立于目标应用实现
- **Character 层**：IP 特定的装饰性表达（如 NERV、EVA-00/01/02、GUTS 角色形象）
- 双装饰层：`#cts-stage`（背景）+ `#cts-chrome`（装饰性 HTML 框架）

#### 4.2 双端口回环策略

CDP 仅绑定 `127.0.0.1`，通过 Owl runtime 调试端口（默认 9335/9341）连接渲染层，避免固定 9229 与其他 CDP 客户端冲突。

#### 4.3 ZIP 主题包 + manifest 校验

`manifest.json` 内含 SHA-256 + 文件大小校验，防止主题被篡改。

#### 4.4 原子备份 + 三层恢复

- 主题恢复（manifest）
- 配置恢复（themes.json）
- 完整卸载（清理注入 + 恢复状态）

#### 4.5 verify-dream-skin.ps1 截图验证

内置 PowerShell 截图对比 + 原生控件存在性检查 + 鼠标事件穿透验证。

### 与 AgentSkin 兼容性分析

两者完全相反的架构定位：
- **AgentSkin**：跨 6 适配器的抽象 14-token 契约
- **Codex-Dream-Skin / Trentct/Codex-Skin**：单应用素材化极致

重叠点在 **codex 适配器** 领域：如果 AgentSkin codex 消费 `codexTheme` TOML，可与 Codex Dream Skin 间接共享主题生态。

### 可借鉴点优先级

1. **P1 — ZIP 主题包 + manifest SHA-256 校验**：防止主题被篡改
2. **P1 — 原子备份 + 三层恢复**：主题切换失败时保留上一状态
3. **P2 — 双端口回环策略**：避免固定 9229 冲突
4. **P2 — Foundation/Character 分层理念**：扩展 Studio 主题编辑器的语义深度

## 6. 推荐最优解方案

### 6.1 P0 — 必须执行（直接提升产品质量）

#### 方案 A：引入运行时质量门禁

**来源**: KyrieWang233/codex-skin-desktop 的实机验证模式

**当前差距**: AgentSkin 的 `check-themes` / `check-theme-staleness` 是**静态校验**（token 完整性、文件存在性、CSS 一致性），没有运行时"试装 → 采样计算样式 → 对比度验证 → 溢出检测"的闭环。

**执行建议**: 在 CDP 注入流程中增加"试装-验证-提交"阶段。对于 codex 和 traework 这类界面变动频繁的应用，每次主题切换后采样 3-5 个关键元素（composer / sidebar / 回复区）的计算样式，验证：
- 文本与背景对比度 ≥ WCAG AA（4.5:1）
- 无水平滚动溢出
- 输入框、按钮等关键组件仍然可见

**执行路径**: 
- [ ] 在 `tests/` 新增 `theme-runtime-check.test.ts` 测试
- [ ] 在 `engines/` 新增 `runtime-validator.mjs` 模块，暴露 API
- [ ] 在 theme 切换 IPC handler 中调用验证器
- [ ] 验证失败时跳过提交，保留上一状态并提示用户

#### 方案 B：doubao.css 背景注入改为独立 div

**来源**: Ky233666/DouBao-Dream-Skin 的独立背景 div + MutationObserver 自愈

**当前差距**: doubao.css 当前通过 `:root` / body 选择器直接注入 `background-image`；豆包切换 `data-theme="dark"|"light"` 时会触发原生 CSS 重设 body 背景，导致主题被覆盖。

**执行建议**:
1. 修改 css 生成器输出的 CSS：不再直接在 body 设 background
2. 在注入逻辑中增加"检测并移除已有背景 div → 插入独立 div → 启动 MutationObserver" 的 runtime 脚本
3. Observer 监听 body 或 documentElement 的 style 变化，检测到背景被重置时恢复

**测试覆盖**:
- [ ] 验证背景 div 在 1 秒 self-heal window 内自愈
- [ ] 验证主题切换时背景 div 平滑过渡
- [ ] 验证关闭注入时背景 div 被彻底移除
