### 2.1 Lumos-789/zcode-cdp — CDP 浏览器接管框架

#### 基本信息
- **创建**: 2026-08-01
- **Stars**: 1 / Forks: 0
- **许可证**: MIT
- **最近更新**: 2026-08-15（13 天前）
- **平台**: macOS / Linux
- **版本**: v0.2.0 (relay 架构)

#### 技术实现

**核心架构**:
```
Agent Clients (ZCode/Claude Code/Python)
    ↓ MCP stdio / 裸 WebSocket / Playwright connect_over_cdp
zcode-cdp-core (治理层)
    ├── zcode-cdp-proxy (状态机懒加载: IDLE→ENSURING→ACTIVE→CLOSING)
    ├── cdpcc (CC 端口预占 + cdp-ensure hook)
    └── zcode-cdp-lease (统一端口租约 / 所有权)
    ↓
N 个已登录 Chrome 实例 (端口池 9223-9229)
```

**核心能力**:

1. **Relay 懒加载代理** — 本地 TCP 中继 + 单常驻 backend，状态机 5 态流转。开 N 个不碰浏览器的窗口 = 0 个 Chrome 进程，激活循环零重启 backend。

2. **端口租约池** — 统一 `mkdir` 原子抢锁 + `leaseId` ownership 校验，防 PID 复用误删新锁。7 个并发端口（9223-9229），杜绝双 owner 竞态。

3. **三层看门狗** — 软看门狗（事件循环延迟 2s）/ CPU 看门狗（主进程 CPU% busy-loop 检测 85% 阈值）/ 硬看门狗（独立 worker 线程，60s 无心跳即 SIGKILL，免疫主线程卡死）。

4. **Profile 继承登录态** — 首次从日常 Chrome `rsync` profile 继承全部登录态，之后独立演化。每端口独立 profile + 不同卡通头像，多账号天然隔离。

5. **三种客户端通道** — MCP 工具（`mcp__cdp__browser_*`）/ 裸 WebSocket / Playwright `connect_over_cdp`，共享同一端口池。

**测试体系**:
- L0 静态契约 marker（14 项）
- L1 租约单元（12 项）
- L1.5 relay 单测（8 场景）
- L2 状态机端到端（11 项，stub backend）
- 半 live 测试：真 playwright-mcp + 真 Chrome 9224

| 维度 | zcode-cdp | AgentSkin |
|------|-----------|-----------|
| 用途 | 浏览器接管（让 agent 操控已登录 Chrome） | 主题注入（为 6 款应用换肤） |
| CDP 连接 | Relay 代理 + 状态机懒加载 | 直连目标应用 CDP |
| 并发治理 | 端口租约池 + 原子 mkdir | epoch-manager + automation-lock |
| 看门狗 | 三层（软/CPU/硬 worker 线程） | 跨平台 watchdog |
| 测试分层 | L0/L1/L1.5/L2 + 半 live | main/ui/visual-regression 三项目 |

|--------|--------|--------|------|

### 2.5 Small-tailqwq/dsh-deep-whale — 鲸鱼娘皮肤系列

#### 基本信息
- **创建**: 2026-08-13
- **Stars**: 1,771 / Forks: 54
- **许可证**: CC BY-NC-SA 4.0（非商业）
- **最近更新**: 2026-08-27（昨天！极其活跃）
- **平台**: Web UI (DSH)
- **开放 Issues**: 14 个

#### 技术实现

**核心架构**:
```
dsh-deep-whale/
├── maid-atelier/          # 深海女仆工坊（亮/暗双版）
│   └── preview/           # 预览图
├── orca-link/             # 虎鲸链路（亮/暗双版）
│   └── preview/           # 预览图
└── skin-manager/          # 通用皮肤发现/切换/配置面板
```

**核心能力**:

1. **皮肤互斥机制** — 通过 patch 层控制（`cordis.patch.yml`），两层（profile + home）写入 `disabled: true/false`。skin-manager 首次重启时检测多套皮肤同时启用 → 自动原子回退到官方默认。

2. **热重载切换** — 皮肤切换走配置热重载，无需重启 DSH。只有新增/删除插件包才需要重启。

3. **GitHub 依赖安装** — 直接以 `github:Small-tailqwq/dsh-deep-whale#path:/skin-manager` 安装，无需 clone。需要 pnpm ≥ 9。

4. **AI 安装技能** — `dsh-skin-install` 技能：AI 读取 INSTALL.md 后引导安装，预置互斥、绝对路径 link、冷启动验证。

5. **皮肤定制** — 每套皮肤有定制选项（如"不那么二次元模式"的可见时段），保存在当前浏览器。

**安装方式**:
```sh
# 一行安装（推荐）
dsh plugin --profile web add 'github:Small-tailqwq/dsh-deep-whale#path:/skin-manager' && \
dsh plugin --profile web add 'github:Small-tailqwq/dsh-deep-whale#path:/maid-atelier' && \
dsh plugin --profile web add 'github:Small-tailqwq/dsh-deep-whale#path:/orca-link'
```

**互斥机制详解**:
- patch 里没有某皮肤的 `disabled` 行 → 该皮肤默认启用
- 两套皮肤同时启用 → 装饰层互相叠加、侧栏/设置区被搅乱
- skin-manager 兜底：首次重启检测 → 自动回退到官方默认并写入互斥行
- 切换时自动把互斥行写入两个 patch 层

## 三、行业趋势总结

### 3.1 MCP 成为 AI Agent 桥接标准

electron-debugger 和 zcode-cdp 都选择通过 MCP（Model Context Protocol）将能力暴露给 AI Agent。这正在成为行业标准：
- electron-debugger：15 个 CDP 调试工具 → MCP stdio server
- zcode-cdp：浏览器操控工具 → MCP stdio server

**对 AgentSkin 的启示**：可将诊断数据、主题管理能力通过 MCP 暴露给 AI Agent，实现"让 AI 帮你调试主题问题"。

### 3.2 状态机 + 看门狗成为 CDP 治理标准

zcode-cdp 的 relay 架构展示了 CDP 连接管理的最佳实践：
- 5 态状态机（IDLE→ENSURING→ACTIVE→CLOSING→IDLE）
- 三层看门狗（软/CPU/硬 worker 线程）
- 端口租约池 + 原子 mkdir 抢锁

**对 AgentSkin 的启示**：engine 层的 CDP 连接管理可参考此模式增强稳定性。

### 3.3 安全皮肤格式成为趋势

LingGlow 的"声明式 JSON + 静态 WebP + SHA-256 校验"模式代表了皮肤格式的安全方向：
- 不含任何可执行代码
- 完整性校验防篡改
- 应用签名 + 公证验证

**对 AgentSkin 的启示**：为 .agentskin-theme 包添加 SHA-256 校验，增强安全性。

### 3.4 AI 安装技能标准化

多个项目（dsh-deep-whale、TRAE-Work-Dream-Skin、LingGlow）都提供了 AI Agent 安装技能：
- dsh-deep-whale：`dsh-skin-install` 技能
- TRAE-Work-Dream-Skin：Codex Skill
- LingGlow：Skin Authoring Skill

**对 AgentSkin 的启示**：可制作标准化的 AI 安装 Skill，让 AI Agent 帮助用户安装、切换、验证主题。
