### 核心架构

CodeDrobe 是一个**多应用换肤 CLI + 运行时**，通过 loopback CDP 注入可逆的 `.codedrobe-theme` 包，不修改应用 bundle 或 `app.asar`。

**内置适配器**：
- `codex` — OpenAI Codex Desktop
- `workbuddy` — Tencent WorkBuddy
- `qoderwork` — QoderWork（CN + global，macOS + Windows）
- `traework` — TRAE SOLO（global + CN，macOS + Windows）

### 技术亮点

1. **resolveDebugPort(s)** — 自动读取 Chromium DevToolsActivePort 文件，处理 `remote-debugging-port=0` 场景；显式端口优先
2. **DOM 快照** — `codedrobe dom snapshot` 捕获只读 DOM 与计算样式，排除文本/表单/可访问性名称/链接/媒体源，为 AI 辅助主题创作提供输入
3. **逐窗口验证** — 二级窗口（弹出聊天、隐藏 overlay）缺少 required landmark 时降级为 `skipped: true`，probe/apply/verify 三者语义一致
4. **图像嵌入** — 源清单声明最多 32 个命名 PNG/JPEG/WebP/GIF，打包后生成作用域 Blob URL，每个图像暴露一个 CSS 变量 `--codedrobe-image-<id>`
5. **遗留主题转换** — `codedrobe theme convert` 将旧版 Codex-only 包转换为声明式 `.codedrobe-theme`，保留 CSS/元数据/文案/艺术字/base-theme 选项

### 与 AgentSkin 对比

| 维度 | CodeDrobe/core | AgentSkin |
|------|----------------|-----------|
| 架构 | CLI + ES Module 库 | Electron 桌面应用 |
| 适配器 | 4 个（codex/workbuddy/qoderwork/traework） | 6 个（+ doubao/zcode） |
| 验证 | 逐窗口 landmark 验证 | 健康检查 + 缺陷修正 |
| 图像 | Blob URL + CSS 变量 | 直接文件引用 |
| 主题格式 | `.codedrobe-theme` 声明式 | 14-token 契约 |

### 可借鉴点

- **resolveDebugPort 模式**：处理 `remote-debugging-port=0` 时自动读取 DevToolsActivePort 文件，AgentSkin 当前硬编码端口，可借鉴此模式增强兼容性
- **逐窗口验证语义**：probe/apply/verify 对二级窗口的降级处理逻辑严谨，可参考改进 AgentSkin 的多窗口场景

### 核心理念

> "Send one image to your Codex and it reskins itself."

**Agent 原生换肤引擎**：用户只需给 Codex 发一张图 + 一句话，Codex 自动克隆仓库、安装、从图片生成主题并应用。

### 技术亮点

1. **双栈端口探测** — dual-stack port probing，自动发现可用 CDP 端口
2. **崩溃去扣 + 熔断器** — crash debounce + circuit breaker，防止注入崩溃导致应用不稳定
3. **装饰命中测试** — decoration hit-testing，确保注入的 UI 元素不影响正常交互
4. **启动看门狗** — Windows 上门禁监控 Codex 重启后自动重应用皮肤；macOS 上 LaunchAgent 实现同样功能
5. **辅助渲染器隔离** — 桌面宠物等辅助渲染器永不注入，保持透明
6. **28 色 token 契约** — THEME-SPEC.md 定义 28 个颜色 token，含裁剪工作流、亮/暗决策树、验收清单
7. **内置主题**：Aurora Veil（暗色路由）、Ember Bloom（亮色路由）、Caishen Readable（暖色低应变）

### 平台支持

- **Windows**：2 条命令（quickstart.ps1 / quick-theme.ps1）
- **macOS**：3 步双击（复用 Codex 捆绑的 Node.js，零依赖）
- **状态持久化**：`%LOCALAPPDATA%\CodexDreamSkin` / `~/Library/Application Support/CodexDreamSkin`

### 与 AgentSkin 对比

| 维度 | codex-autoskin | AgentSkin |
|------|----------------|-----------|
| 目标应用 | 仅 Codex | 6 应用 |
| 交互范式 | 给 Codex 发图 | Electron 应用内 |
| 主题生成 | 自动取色 + 亮/暗路由检测 | Visual Analyzer + 手动 |
| 守护进程 | 启动看门狗自动重应用 | 无 |
| 安全机制 | 双栈端口探测 + 熔断器 | epoch-manager + automation-lock |

### 可借鉴点

- **启动看门狗**：应用重启后自动重应用皮肤，AgentSkin 当前缺少此机制
- **双栈端口探测 + 熔断器**：增强注入稳定性，可参考改进 AgentSkin 的端口探测逻辑

- **热重载**：编辑 JSON 无需重启

### 🎯 关键设计决策：语义色保护

> "Left at the base `dark` preset on purpose: `success`, `error`, `warning`, `diff` colors — so status colors stay semantically green/red/yellow in every theme."

**每个主题只覆盖**：
- `claudes` + `shimmer`（品牌强调色 = 主题强调色）
- `text` / `inactive` / `subtle`（前景、可读次要文本、装饰性发丝线）
- `promptBorder` / `suggestion` / `rate_limit_fill`（强调色匹配）
- `permission` / `planMode`（第二强调色）
- `userMessageBackground`（+hover）：抬高表面，比 bg 高一档

**故意不覆盖**：`success`、`error`、`warning`、`diff` — 状态色保持语义化。

### WCAG 对比度验证

- AAA 对比度用于主要文本
- AA 对比度用于前景强调色和可读次要文本
- WCAG 非文本地板用于功能边框和指示器
- `subtle` 仅用于装饰性发丝线，从不用于可读次要文本

### 与 AgentSkin 对比

| 维度 | claude-code-50-dark-themes | AgentSkin |
|------|---------------------------|-----------|
| 目标应用 | Claude Code CLI | 6 桌面应用 |
| 主题格式 | JSON 调色板 | 14-token 契约 |
| 语义色保护 | 明确保护 success/error/warning/diff | 14 token 含语义角色 |
| 对比度验证 | WCAG AAA/AA 强制 | WCAG 2.1（THEME_SPEC.md） |
| 安装方式 | Claude Code 插件市场 | Electron 应用内 |

### 可借鉴点

- **语义色保护原则**：明确区分"可自由装饰的强调色"与"必须保持语义的状态色"，AgentSkin 的 14 token 可参考此原则进一步细化
- **WCAG 对比度工具**：`theme-contrast` Python 工具可独立用于 CI 检查，可借鉴集成到 AgentSkin 的校验流程
