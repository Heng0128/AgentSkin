## 二、逐项目深度分析

### 2.1 b-nnett/codex-plusplus ⭐3,751

**定位**：Codex Desktop 的大型跨平台改造系统，通过修补 app.asar 加载本地 tweak 运行时。

**技术架构**：
- **安装器**：修补 Codex `app.asar` → 加载 Codex++ loader
- **运行时**：驻留用户数据目录，发现并加载 tweak
- **Tweak 系统**：renderer 进程 + main 进程 双 scope
- **原生桥接**：Owl 运行时检测、AppKit/Metal 支持
- **安全机制**：safe-mode、签名验证、备份还原

**关键创新点**：
1. **Owl 运行时适配** — 1.0.0 引入的原生桥接，支持 AppKit、Metal、MetalKit
2. **Browser-Host 模式** — 将 Codex React UI 暴露在浏览器标签页中，便于自动化
3. **Tweak SDK** — 公开的 tweak 开发 API（settings、windows、cdp、native）
4. **Watcher 自修复** — Codex 更新后自动重打补丁

**与 AgentSkin 对比**：
| 维度 | codex-plusplus | AgentSkin |
|------|----------------|-----------|
| 注入方式 | 修改 app.asar + 运行时加载 | 外部 CDP WebSocket |
| 修改持久性 | 持久（须重打补丁） | 运行时（断开即还原） |
| 原生桥接 | 支持（Owl/AppKit/Metal） | 无 |
| 多应用支持 | 仅 Codex | 6 个 AI 应用 |
| 安全模型 | safe-mode + 签名 | epoch-manager + automation-lock |

**可借鉴点**：
- ⚠️ **watchers 自修复模式** — AgentSkin 的 adapter 在目标应用更新后需要手动适配，可借鉴这种自动检测+修复思路
- ⚠️ **safe-mode 机制** — 禁用所有 tweak 而不删除，对 AgentSkin 的"紧急停止"功能有参考价值
- ❌ **原生桥接** — AgentSkin 定位为运行时注入引擎，不涉及原生层，不适用

### 2.2 MagMueller/aios ⭐0（新项目）

**定位**：任意 macOS Electron 应用的实时修改套件，一次性安装后可通过配置文件热重载 UI。

**技术架构**：
- **主进程 Agent**：修补入口文件 → `require('./aios-agent')`
- **配置热重载**：`fs.watchFile('/tmp/aios-config.json')` → 1 秒内生效
- **CDP 端点**：`--remote-debugging-port=9222` 暴露 WebSocket
- **安装器**：解包 asar → 修补入口 → 重打包 → ad-hoc 重签名

**三轨修改模式**：
1. **Config 文件** — 编辑 JSON 配置，agent 自动重载 CSS/JS
2. **CDP 直连** — `node scripts/drive.js '<js>'` 单次执行
3. **Agent 替换** — 修改 `agent.js` 本身，需重装

**关键创新点**：
1. **1 秒热重载** — 配置文件修改后立即反映到所有 BrowserWindow
2. **per-app 配置示例** — Slack/Discord/Linear/Superset/Cursor 等
3. **SKILL.md 自动化** — 让 Claude Code 自动安装到新应用

**与 AgentSkin 对比**：
| 维度 | aios | AgentSkin |
|------|------|-----------|
| 安装方式 | 一次性修补入口文件 | 无需安装，纯运行时 |
| 配置驱动 | JSON 配置文件 | 14-token 主题契约 |
| 热重载 | fs.watchFile 1秒生效 | 须重新注入 |
| 跨平台 | 仅 macOS | macOS + Windows |
| 应用覆盖 | 任意 Electron | 6 个 AI 专属 |

**可借鉴点**：
- ✅ **配置文件热重载模式** — AgentSkin 可以考虑为开发者模式添加类似的 CSS 热重载
- ⚠️ **per-app 配置示例** — AgentSkin 已有类似概念（adapter patterns）
- ❌ **入口文件修补** — 违反 AgentSkin "零修改应用" 原则

### 2.4 oussamaexe/electron-debugger ⭐1

**定位**：面向 AI 助手（MCP）的 Electron 调试服务器，通过 CDP 暴露 15 个工具。

**15 个 MCP 工具**：

| 工具 | 描述 |
|------|------|
| `get-dom-snapshot` | DOM 树快照 |
| `get-element-box` | CSS 选择器边界框 |
| `get-element-styles` | 计算样式 |
| `take-screenshot` | 页面/元素截图 |
| `get-console-logs` | 控制台日志 |
| `get-metrics` | 性能指标（FPS、内存、DOM 节点） |
| `click-element` | 点击元素 |
| `type-text` | 输入文本 |
| `highlight-element` | 视觉高亮 |
| `list-windows` | 列出所有 BrowserWindow |

**核心架构**：
```
Electron App (--remote-debugging-port=9222)
    ↓ CDP WebSocket
electron-debugger MCP Server
    ↓ MCP Protocol
AI Assistant (Claude/Cursor/...)
```

**关键创新点**：
1. **CDP → MCP 桥接** — 将 CDP 命令直接暴露为 MCP 工具
2. **零依赖** — 仅需 `--remote-debugging-port` 即可工作
3. **AI Agent 友好** — 专为 AI 助手设计的调试接口

**与 AgentSkin 对比**：
| 维度 | electron-debugger | AgentSkin |
|------|-------------------|-----------|
| 用途 | 调试/检查 | 主题注入 |
| 协议 | CDP → MCP | CDP 直接 |
| 用户 | AI Agent | 终端用户 |
| 工具数 | 15 | N/A |
| 持久性 | 临时调试 | 持续注入 |

**可借鉴点**：
- ✅ **MCP 工具桥接** — AgentSkin 可以暴露一组调试 MCP 工具（截图、DOM 检查、注入验证）
- ✅ **CDP 命令封装** — 可以参考其工具定义方式，为 AgentSkin 增加开发者调试接口
- ✅ **"为 AI Agent 设计" 的视角** — 值得 AgentSkin 借鉴，让注入状态对 AI 透明

### 2.5 ArthurLobopro/electron-css-injector ⭐2

**定位**：基于 Electron 内部 protocol API 的 CSS 注入包，应用内集成方案。

**技术原理**：
- 使用 Electron 的 `protocol.registerFileProtocol` 或 `protocol.interceptFileProtocol`
- 在 DOMContentLoaded 时注入样式
- 主进程 + preload 双端集成

**与 AgentSkin 对比**：
- 这是**应用内集成方案**，与 AgentSkin 的**外部 CDP 注入**完全不同
- 适用于构建时集成，不适用于运行时换肤
- 对 AgentSkin 架构无直接参考价值

**可借鉴点**：
- ❌ 不适用 — 架构路线不同

## 四、推荐方案

### P1 — MCP 调试工具桥接（高可行性，高价值）

**目标**：为 AgentSkin 暴露一组 MCP 调试工具，让 AI 助手能验证注入效果、截图对比、获取 DOM 快照。

**实现范围**：
1. 新增 `scripts/agent-skin-mcp-server.mjs` — MCP server 入口
2. 暴露 6 个核心工具：
   - `verify-injection` — 验证当前注入状态
   - `take-screenshot` — 截图当前目标应用
   - `get-dom-snapshot` — 获取渲染 DOM 快照
   - `get-applied-theme` — 获取当前应用的主题
   - `list-targets` — 列出所有可注入目标
   - `restore-original` — 一键还原
3. 复用现有 CDP 连接（engines/）

**可行性评估**：
- ✅ 不涉及注入架构修改（不触发 RFC）
- ✅ 不涉及新增适配器
- ✅ 复用现有 engines/ 能力
- ✅ 独立脚本，可单独测试

**预估工作量**：
- 核心 MCP server：~150 行
- 工具实现：~300 行
- 测试：20+ 个用例
- 总计约 2-3 小时

### P2 — CDP 会话管理增强（中可行性，中价值）

**目标**：参考 electron-cdp 的 MainSession 封装，改进 AgentSkin 的 CDP 连接管理。

**实现范围**：
1. 增强 `src/engine/` 的 CDP 客户端
2. 添加 iframe/worker 自动附着
3. 添加 SuperJSON 序列化支持复杂类型

**可行性评估**：
- ⚠️ 涉及 engine 层修改（需评估是否触发 RFC）
- ✅ 不改变外部 API
- ✅ 向后兼容

**预估工作量**：
- 需先评估影响范围
- 如需 RFC，工作量较大

### P3 — 紧急停止机制（低优先级，参考性质）

**目标**：添加 safe-mode 开关，紧急情况下禁用所有注入。

**可行性评估**：
- ✅ 可实现为快速切换开关
- ✅ 不改变核心架构
