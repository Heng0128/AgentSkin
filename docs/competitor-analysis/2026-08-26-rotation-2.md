## 核心发现

### 行业趋势 1：运行时修复成标配
dream-skin-forge 的"module-matrix"将运行时 UI 问题归类为 header/sidebar/right-panel/cache/renderer-selector 五个维度，与 AgentSkin 的 diagnostics Store 异曲同工，但更聚焦于视觉注入的运行时状态管理。

### 行业趋势 2：氛围感知（Ambient Awareness）兴起
workbuddy-ambient-seek 的"首页展示 → 工作页收敛 → 详情页淡出"三级模式，与传统的"全有/全无"注入模式截然不同。这种基于页面状态的上下文感知注入，是 AgentSkin 目前缺失的能力。

### 行业趋势 3：样式隔离与浮动层
codexskin 的"过滤 avatar-overlay"策略和 Tauri 的 WebView 隔离机制，启示多窗口 Electron 应用（如豆包的宠物窗口）需要选择性注入。

### AgentSkin 差异化优势矩阵

| 能力 | AgentSkin | 最强竞品 | 差距 |
|------|-----------|---------|------|
| 工程质量体系 | 10 不变量 + 全量校验 | dream-skin-forge（shell 测试） | AgentSkin 完胜 |
| 14-token 主题契约 | 跨应用统一抽象 | ambient-skin（OKLCH 感知） | 各有优势 |
| 6 适配器深度覆盖 | traework/qoderwork/workbuddy/doubao/codex/zcode | workbuddy-ambient（单应用） | AgentSkin 完胜 |
| 运行时修复 | diagnostics Store | dream-skin-forge（module-matrix） | 各有优势 |
| 氛围感知注入 | ❌ 无 | workbuddy-ambient-skin | **竞品领先** |
| 多窗口样式隔离 | 进程级 patch | codexskin（CSS 选择器过滤） | **竞品领先** |
| Skill 创作协议 | Studio 可视化 | WorkBuddy-theme-skill（SKILL.md） | AgentSkin 优势 |

### 1. jiarong0423/dream-skin-forge

> **一句话**：将运行时 UI 故障修复 productize 的微型引擎，工程方法论大于代码本身。

**核心数据**：
- Stars: 1 | Forks: 0 | 创建: 2026-07-25 | 最后更新: 2026-07-25
- Language: JavaScript | License: MIT | 平台: macOS 独占
- 贡献者: 1 人（initial commit only）

**架构创新 — Module Matrix**：
```
flowchart LR
  A["Theme Pack Sources"] --> B["pack.json Contract"]
  B --> C["validate-packs.sh"]
  C --> D["forge-gate.sh"]
  G --> H["Active Theme State<br/>with backup"]
  H --> I["injector.mjs"]
  I --> J["Renderer-safe Data URLs"]
  K --> L["Hot-swap Bay<br/>select dropdown"]
  O --> P["module-matrix.mjs<br/>budget and ownership gate"]
```

运行时修复四维矩阵：

| 故障类型 | 检测方式 | 修复策略 |
|---------|---------|---------|
| Hot-swap selector 消失 | renderer 跳过了 core apply | injector.mjs 检查 hot-swap DOM 完整性，不完整则重送 core |
| Theme-pack cache 失效 | cache hash 一致但 payload 失效 | 检查 schema + data URL 头，不安全则失效重送 |
| Sidebar row 变形 | 原生 icon gutter 与注入 glyph 冲突 | 检测 native side gutter 后 fail-closed |
| Titlebar 接缝 | header divider 被 sidebar overlay 遮挡 | CSS 改由 header `::after` 从 left shell width 后开始 |

**AgentSkin 可借鉴**：
- module-matrix 思路 → 映射到 diagnostics Store，注入失败时自动路由到对应修复策略
- fail-closed 原则 → 选择器冲突时不强行注入，而是回退到安全态
- `plan/activate/rollback` 三段式 CLI → 可移植到 theme preview store

**AgentSkin 不采纳**：
- 仅 macOS 单平台
- 单 theme-pack 粒度（AgentSkin 是 14-token bundle 粒度）
- 无 Windows PowerShell 支持

### 3. leeandrew94/workbuddy-ambient-skin

> **一句话**：唯一仍在活跃更新的 WorkBuddy 竞品（8/5 仍提交），氛围感知 + OKLCH 色彩 + 浮球 UI 三件套。

**核心数据**：
- Stars: 1 | Forks: 1 | 创建: 2026-07-21 | **最后更新: 2026-08-05（仍在活跃！）**
- Language: JavaScript | License: 未声明 | 平台: macOS + Windows
- 固定 CDP 端口: 9347 | Node.js 22+

**核心创新 1 — OKLCH 感知色彩提取**：
对上传图片在 OKLCH 感知均匀色彩空间进行采样，提取主色与差异化辅色，自动判断明暗、视觉焦点和文字安全区。

流程：
1. 缩放图片至最长边 1600px
2. OKLCH 空间分桶（12 色相 × 3 明度）
3. 感知亮度中位数 → 选择深色/浅色界面
4. 色相差最大的两个桶 → 主色 + 辅色
5. 自动校正强调色与文字色的 WCAG 对比度

**核心创新 2 — 氛围收敛（Ambient Convergence）**：
| 页面状态 | 背景强度 | 玻璃面板 | 说明 |
|---------|---------|---------|------|
| 首页 (Home) | 100% | 高透明 | 完整氛围展示 |
| 工作页 (Work) | 40% | 中透明 | 降低对比，聚焦内容 |
| 详情页 (Detail) | 15% | 低透明 | 几乎淡出，纯阅读 |

**核心创新 3 — 浮球菜单（Draggable Floating Ball）**：
- 可拖拽，松手后吸附到最近左右边缘
- 记住位置（跨会话持久化）
- 双击复位到右上角
- 菜单根据浮球位置自动选择展开方向

**内置主题（4 套）**：

| Paper Aurora | 浅灰冰蓝 · 通透办公 | CSS 渐变生成（非图片） |
| Miku Neko Maid | 青白亮色 · 轻粉 | OKLCH 从图片提取 |
| Doraemon Snow Fortune | 冰雪蓝 · 灯笼红 · 暖金 | OKLCH 从图片提取 |
| Raiden Eternal Thunder | 深紫雷光 · 浅紫玻璃 | OKLCH 从图片提取 |

**AgentSkin 可借鉴 — 高价值**：
- L1: OKLCH 引擎 → Studio 图片主题生成器（P0，直接落地）

## 推荐方案

### P0 — 必须执行（直接提升产品质量）

#### 方案 A：Studio OKLCH 图片主题生成器（L1）

**来源**: leeandrew94/workbuddy-ambient-skin 的 OKLCH 感知色彩引擎

**当前差距**: AgentSkin Studio 的壁纸导入仅做文件搬运，不分析图片色彩特征，更不自动生成 14-token 配色方案。

**执行建议**:
1. 新增 `scripts/lib/oklch-extract.mjs` 模块
2. 输入：图片路径（支持 PNG/JPEG/WebP）
3. 处理流程：
   - 缩放到最长边 800px（性能考虑）
   - 转换到 OKLCH 色彩空间
   - 12 色相 × 3 明度分桶
   - 提取主色（最大桶）+ 辅色（色相差最大桶）
   - 感知亮度中位数判定 dark/light mode
   - 自动映射到 14 个 token
4. 输出：14-token manifest JSON

**测试覆盖**:
- [ ] 纯色图 → 准确提取主色
- [ ] 暗色图 → 自动选择 dark mode
- [ ] 亮色图 → 自动选择 light mode
- [ ] 高饱和度图 → 自动降级到 WCAG AA 合规
- [ ] 人物图 → 避开主体区域提取背景色

**文件路径**:
- `scripts/lib/oklch-extract.mjs`
- `scripts/extract-theme-from-image.mjs`（CLI 入口）
- `tests/main/oklch-extract.test.ts`

#### 方案 B：多窗口注入过滤（L2）

**来源**: lntomF/codexskin 的 avatar-overlay 过滤策略

**当前差距**: AgentSkin 的 doubao/codex 注入器采用全局 patch（`patchWindowsAdapters`），无法区分主页面与宠物/设置/弹窗等子窗口，可能导致壁纸错位。

**执行建议**:
1. 在 `src/legacy/agentskin-core-runtime.ts` 的 CDP 注入前增加 target 过滤
2. 过滤规则：
   - `type !== "page"` → 跳过
   - URL 匹配 `avatar-overlay|pet|settings|modal` → 跳过
   - 白名单优先于黑名单

**测试覆盖**:
- [ ] 主页面正常注入
- [ ] overlay 页面被跳过
- [ ] 设置弹窗被跳过
- [ ] URL 白名单覆盖

**文件路径**:
- 修改 `src/legacy/agentskin-core-runtime.ts`
- `tests/main/injection-target-filter.test.ts`

#### 方案 C：单实例守护竞争检测（L3）

**来源**: comeonzhj/WorkBuddy-theme-skill 的守护进程竞争检测

**当前差距**: AgentSkin 多次启动可能遗留多个主进程实例，导致 IPC 通道竞争和 UI 闪烁。

**执行建议**:
1. 在 main 进程启动时检测已有实例
2. 通过 `app.requestSingleInstanceLock()` 实现
3. 第二个实例检测到锁占用时，发送消息给第一个实例后退出
4. 被唤醒的第一个实例收到消息后闪烁 Dock 图标提示用户

**测试覆盖**:
- [ ] 单实例正常启动
- [ ] 双实例时第二个退出
