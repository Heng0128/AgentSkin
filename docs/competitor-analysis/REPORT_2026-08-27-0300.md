### 2.2 技术架构亮点

#### 2.2.1 挂件动画系统（合成层位移）

LingGlow 的「挂件」是其核心 UX 创新——在输入框附近漂浮的装饰性动画元素：

- **合成层位移**: 使用 CSS `transform` 而非 `top/left` 实现动画，避免触发重排
- **输入框锚点复用**: 挂件按当前输入框宽度计算运动路程，跟随输入框尺寸变化
- **智能启停**: 只在真实生成回复时运行动画；空闲、窗口进入后台或页面隐藏时立即暂停
- **端点掉头**: 挂件沿输入框完整往返并在端点掉头，呈现自然漂浮感

**对 AgentSkin 的启示**: 我们的 doubao 适配器可以借鉴这种「合成层位移 + 智能启停」模式，减少挂件动画对性能的影响。

#### 2.2.2 连续阅读遮罩

根据每套皮肤的表面色、文字色和照片明暗自动计算连续阅读遮罩：

- 提升豆包正文、侧栏和输入框在明暗复杂背景上的可读性
- 保留原生输入框边缘效果
- 基于色彩感知计算而非简单叠加

**对 AgentSkin 的启示**: 这是一种「可访问性兜底」机制，与我们的 WCAG AA 合规方向一致。可考虑在运行时注入时计算背景亮度，动态调整文字对比度。

#### 2.2.3 安全设计

- **安全目录**: 只允许声明式 JSON 与静态 WebP，包、定义文件和图片均校验 SHA-256
- **安全更新**: App 更新校验摘要、Bundle ID、Developer Team ID、Developer ID 签名与 Apple 公证
- **可恢复**: 应用前检查客户端签名和兼容级别，保留恢复官方原版入口
- **失败关闭**: 当客户端版本或能力未经验证时进入通用安全模式

## 三、项目 2: Finderchangchang/codex-autoskin — Agent-native 换肤引擎

### 3.1 基本信息

- **Stars**: 117 ⭐（社区热度高）
- **Forks**: 22
- **License**: MIT
- **平台**: Windows (Store Codex) + macOS
- **当前版本**: v2.0.0 (2026-07-16)
- **仓库体积**: 11MB
- **最后更新**: 2026-08-24（文档更新）

### 3.2 核心创新：Agent-native 工作流

codex-autoskin 的核心理念是「发一张图给你的 Codex，它自己给自己换肤」：

```
用户发图 → Agent 读取 THEME-SPEC.md → 自动提取调色板 → 生成主题 → 应用
```

#### 3.2.1 THEME-SPEC.md 规范即生成器

这是本项目最具创新性的设计——将主题规范写成 Agent 可读的格式：

- 28 个颜色 token 的完整定义
- 四种艺术角色的裁切工作流
- 亮/暗决策树
- 验收清单（Agent 可自验证）

**对 AgentSkin 的启示**: 我们的 14-token 契约可以扩展为 Agent 可读的 THEME-SPEC.md，让 AI 助手能自动生成和验证主题。

#### 3.2.2 健壮性设计

- **双栈 CDP 探测**: 同时探测 IPv4/IPv6 回环
- **watcher 防抖熔断**: 文件变更监控 + 防抖 + 熔断器模式
- **命中测试 QA**: 装饰元素命中测试，确保不遮挡交互区域
- **启动 watcher**: Windows 启动时 / macOS LaunchAgent 自动重应用

#### 3.2.3 Manifest 驱动引擎

- 加主题 = 放一个文件夹，零改码
- `theme.json` + 图片 = 完整主题
- `set-theme` 一句话切换（界面零控件）

### 3.3 技术栈

```
PowerShell / POSIX shell + Node.js + Chrome DevTools Protocol
零第三方依赖
```

| THEME-SPEC.md Agent 可读规范 | 高 | P0 | 让 AI 自动生成和验证主题 |

## 八、推荐执行方案

### 8.1 方案 A: THEME-SPEC.md Agent 可读规范（P0，高可行性）

**来源**: codex-autoskin 的 THEME-SPEC.md 设计

**目标**: 将 AgentSkin 的 14-token 契约扩展为 AI Agent 可读可执行的规范文档

**实施步骤**:
1. 创建 `docs/THEME-SPEC.md`，用结构化 Markdown 定义 14-token 契约
2. 添加亮/暗决策树
3. 添加验收清单（Agent 可自验证）
4. 添加裁切工作流（参考 codex-autoskin 的四角色裁切）

**预期收益**: AI 助手能自动生成和验证主题，降低主题制作门槛

### 8.2 方案 B: CDP 连接自动重连（P1，高可行性）

**来源**: electron-debugger 的自动重连机制

**目标**: 在 engines/ 层添加 WebSocket 断开自动重连

**实施步骤**:
1. 在 CDP 连接层添加 `autoReconnect` 选项
2. 实现指数退避重连策略
3. 添加重连事件通知到主进程

**预期收益**: 客户端重启或网络抖动后自动恢复注入，提升稳定性

### 8.3 方案 C: 运行时 WCAG 兜罩（P1，高可行性）

**来源**: LingGlow 的连续阅读遮罩

**目标**: 在注入时动态计算背景亮度，调整文字对比度

**实施步骤**:
1. 在 CSS 注入前计算背景色感知亮度
2. 动态生成 `color` / `text-shadow` 覆盖
3. 添加 `--agentskin-readable` CSS 变量

**预期收益**: 复杂背景上的文字可读性提升，减少手动调整

### 8.4 方案 D: MCP 工具暴露（P2，中可行性）

**来源**: electron-debugger 的 MCP 服务器模式

**目标**: 将 AgentSkin 的 CDP 能力暴露为 MCP 工具

**实施步骤**:
1. 创建 MCP 服务器入口
2. 暴露 `get-dom-snapshot` / `take-screenshot` / `verify-injection` 等工具
3. 支持 stdio 和 HTTP 两种传输

**预期收益**: AI Agent 能直接验证注入效果，实现自动化 QA
