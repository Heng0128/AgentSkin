## 二、深度分析

### 2.1 CodeDrobe/core — 统一换肤运行时

#### 核心发现

CodeDrobe 是目前生态中**架构最完整**的统一换肤平台，采用三层架构：

1. **Desktop** — 普通用户的可视化主题商店
2. **Core CLI** — 开发者的命令行工具（`codedrobe apply/verify/restore/pack`）
3. **Skill** — AI 创作者的技能包（参考图 → 皮肤 → 验证 → 发布）

#### 技术亮点

**统一主题包格式 `.codedrobe-theme`**：
- 一个文件 = 一个主题（清单 + CSS + 内嵌图片）
- 一个包适配多个应用（同一套视觉，按 adapter 选择 CSS）
- Schema 驱动的兼容性预检（声明依赖的界面节点，不兼容明确报错）
- **零 JavaScript**：主题包只有声明式配置、CSS 和图片，是"数据"不是"程序"

**适配器架构**：
- 内置 `codex`、`workbuddy`、`qoderwork`、`traework` 四个适配器
- 每个适配器定义了稳定的跨路由 renderer landmarks
- 支持 required/recommended/contexts 三级验证策略
- 主题作者应遵循"prefer recommended, reserve required for genuinely malfunctioning landmarks"

**DOM 快照 API**：
```bash
codedrobe dom snapshot --app codex --output codex-dom.json
```
- 记录活跃主题、元素关系、语义类、稳定选择器候选、边界框、landmark 匹配、主题相关计算样式
- 刻意排除文本内容、表单值、可访问名称、query/hash 数据、链接、媒体源
- 为 AI 辅助主题创作提供只读 API

**验证策略**：
- 兼容性按渲染窗口判断：缺少 required landmarks 的次要窗口降级为 `"skipped": true`
- Verify 永不跳过已安装主题的窗口，确保回归仍被检测
- 缺失 recommended landmarks 仅返回警告不阻塞注入
- 上下文检查仅在 `when.any` landmarks 可见时执行

#### 与 AgentSkin 对比

| 维度 | CodeDrobe | AgentSkin |
|------|-----------|-----------|
| 主题格式 | `.codedrobe-theme` 声明式包 | 14-token JSON + CSS |
| 适配器 | 4 个（codex/workbuddy/qoderwork/traework） | 6 个（+ doubao/zcode） |
| 验证机制 | Schema 预检 + DOM 快照 + 三级 landmarks | SHA256 SUMS + WCAG |
| 图片处理 | CSS 变量映射（`--codedrobe-image-<id>`） | 14-token 映射 |
| 商店 | 有官方社区主题商店 | 无（禁止自建 CDN） |

#### 可借鉴点

1. **Schema 驱动的兼容性预检** — 主题声明依赖的界面节点，安装前预检
2. **DOM 快照 API** — 为 AI 辅助主题创作提供只读接口
3. **三级 landmarks 验证** — required/recommended/contexts 分层策略
4. **零 JavaScript 主题包** — 声明式配置更安全，但 AgentSkin 已有 14-token 契约

**可行性评估**：P1 — Schema 预检和 DOM 快照 API 可参考，但 AgentSkin 的 14-token 契约已足够声明式

### 2.2 cdredfox/workbuddy-skin-studio — WorkBuddy 换肤工作室

#### 核心发现

WorkBuddy 生态中**传播度最高**的换肤工具（168 stars），特点是"一张图片就是一个主题"的极简 UX。

#### 技术亮点

**图片驱动的主题生成**：
- 任意 PNG/JPG/JPEG/WebP 直接生成皮肤
- Canvas 自动取色（主色、辅色、面板底色、文字色）
- 根据 surface 明度自动切换 `data-vscode-theme-kind`

**右上角 🎨 菜单**：
- 注入后 WorkBuddy 右上角出现主题切换按钮
- 所有已装主题和原生界面即点即换
- 自定义图片上传后自动取色并持久化（localStorage）

**极简主题格式**：
```json
{
  "schemaVersion": 1,
  "id": "my-skin",
  "name": "My Skin",
  "hero": "hero.webp",
  "colors": {
    "accent": "#24C9D7",
    "secondary": "#EF8FD3",
    "surface": "#F7FBFF",
    "text": "#17344F"
  }
}
```

**CSS 变量覆盖**：
- 通过 60+ 个 `--cb-*` 变量实现全局换色
- 给 `#root` 加背景图，容器设透明让底图透出

#### 与 AgentSkin 对比

| 维度 | workbuddy-skin-studio | AgentSkin |
|------|----------------------|-----------|
| 主题格式 | 4 色 + hero 图片 | 14-token 完整契约 |
| 取色方式 | Canvas 客户端取色 | Pillow 服务端 + medianCut |
| 切换 UX | 右上角菜单即时切换 | Electron 应用内切换 |
| 持久化 | localStorage | 文件系统 + IPC |
| 平台 | macOS + Windows | macOS + Windows |

#### 可借鉴点

1. **右上角菜单即时切换** — 无需重启应用即可预览主题
2. **Canvas 客户端取色** — 无需服务端依赖，纯浏览器端完成
3. **极简主题格式** — 降低用户创建门槛

**可行性评估**：P1 — 右上角菜单即时切换 UX 值得参考，但 AgentSkin 的 14-token 契约更完整

### 2.4 tintinweb/electron-inject — CDP 注入经典范本

#### 核心发现

**最经典的 Electron CDP 注入工具**（379 stars），Python 实现，是理解"CDP 注入"机制的最佳范本。

#### 技术亮点

**核心机制**：
```bash
electron_inject --enable-devtools-hotkeys - /path/to/electron/app
```
- 利用远程调试控制台向 Electron 应用注入 JavaScript
- 支持启用开发者工具热键（F12/F5）
- 支持自定义渲染脚本注入（`--render-script`）
- 支持超时重试注入（`--timeout`）

**技术实现**：
- Python + pip 安装
- 通过 `--remote-debugging-port` 连接
- 支持将 DevTools 在浏览器中打开（`--browser`）

#### 与 AgentSkin 对比

| 维度 | electron-inject | AgentSkin |
|------|----------------|-----------|
| 语言 | Python | TypeScript |
| 用途 | 调试/注入任意 Electron 应用 | 主题定制引擎 |
| 注入方式 | CDP Runtime.evaluate | CDP + 14-token 映射 |
| 复杂度 | 单文件脚本 | 完整 Electron 应用 |

#### 可借鉴点

1. **CDP 注入模式** — 理解"连接 → 注入 → 执行"的标准流程
2. **超时重试机制** — `--timeout` 参数确保注入成功

**可行性评估**：P2 — 作为 CDP 注入的参考实现，AgentSkin 已有成熟的 CDP 引擎

## 四、落地执行方案

### P0 — Schema 驱动的兼容性预检

**目标**：为主题包引入 schema 验证机制，安装前预检兼容性

**实现路径**：
1. 定义 `theme-manifest-schema.json`，包含：
   - `required_landmarks`: 主题依赖的必需界面节点
   - `recommended_landmarks`: 推荐的界面节点
   - `contexts`: 路由特定的上下文验证
2. 实现 `validateThemePackage()` 函数
3. 在 `applyTheme()` 前调用预检
4. 不兼容时明确报错，列出缺失的 landmarks

**测试计划**：
- 新增 15-20 个测试用例
- 覆盖：兼容/不兼容/部分兼容/边界情况

### P1 — DOM 快照 API

**目标**：为 AI 辅助主题创作提供只读 DOM 快照接口

**实现路径**：
1. 新增 `scripts/dom-snapshot.mjs` 工具
2. 连接 CDP → 获取 DOM → 过滤敏感信息 → 输出 JSON
3. 记录：元素关系、语义类、稳定选择器候选、边界框、计算样式
4. 排除：文本内容、表单值、可访问名称、query/hash、链接、媒体源

**测试计划**：
- 新增 10-15 个测试用例
- 覆盖：过滤准确性、选择器稳定性、性能

### P2 — 右上角菜单即时切换 UX

**目标**：在目标应用中注入主题切换菜单，无需重启即可预览

**实现路径**：
1. 分析 WorkBuddy 的右上角菜单注入方式
2. 为 AgentSkin 的适配器添加"轻量注入"模式
3. 实现主题切换菜单组件
4. 持久化用户选择到 localStorage
