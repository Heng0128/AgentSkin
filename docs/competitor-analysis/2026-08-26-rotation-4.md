## 2. 核心发现与行业趋势

### 趋势 1：Tweak Loader 架构成为大型竞品的标配
`codex-plusplus` 的 tweak manifest + runtime 分离架构，将"应用修改"productize 为可分发、可验证、可热更新的 tweak 包。这与 AgentSkin 的 bundle 安装流程异曲同工，但更聚焦于"用户可编写扩展"而非"主题包"。

### 趋势 2：Agent-native 交互范式兴起
`raccoon-dream-skin` 的"说一句话就换肤"模式，将 AI Agent 从"工具辅助"提升为"操作代理"。用户无需理解主题格式、选择器、CSS，直接用自然语言表达意图，Agent 完成全部技术操作。

### 趋势 3：零残留清理成为工程刚需
`codex-skin-manager` 的 `purge-all.mjs` 是目前最完善的主题痕迹清理方案。白名单式清理 DOM ID、CSS 变量、全局状态、粒子定时器，杜绝交叉样式污染。这反映了用户对"切换主题后上一主题残留"的痛点。

### 趋势 4：通用 Electron 注入框架走向 Skill 化
`aios` 的 SKILL.md 将 Electron 注入技术封装为 Claude Code Agent 可理解的技能协议，使任意 Electron 应用的修改可被 AI Agent 自动化执行。这标志着注入技术从"手动操作"走向"Agent 自动化"。

### 趋势 5：应用内 CSS注入 SDK 层成熟
`electron-css-injector` 展示了通过 Electron protocol API 在 preload 中注入 CSS 的轻量方案。与外部 CDP 注入形成互补：应用内方案更稳定（不依赖调试端口），但需要修改应用构建。

### 4.2 MagMueller/aios

> **一句话**：任意 macOS Electron 应用的实时修改套件，三轨注入 + Claude Code Skill 协议。

**核心数据**：

| 指标 | 数据 |
|------|------|
| Stars | 0（极新项目） |
| Forks | 0 |
| 语言 | JavaScript |
| License | 未声明 |
| 创建日期 | 2026-04-11 |
| 最后更新 | 2026-04-11（仅 1 commit） |
| 平台 | **macOS 独占** |

**三轨注入架构**：

| 轨 | 机制 | 能力 | 延迟 |
|----|------|------|------|
| Rail 1 | Config file watcher (`/tmp/aios-config.json`) | CSS + 持久化 JS | < 1s |
| Rail 2 | Main-process hooks (agent.js) | BrowserWindow/session/webRequest | 即时 |
| Rail 3 | CDP (127.0.0.1:9222) | 任意 JS 注入，绕过 CSP | 即时 |

**CSP Bypass 经验**：
- 现代 Electron 应用（Superset、Linear、Discord、Slack）设置严格 CSP
- `<script>` 标签注入被浏览器阻止执行
- 解决方案：`webContents.executeJavaScript()` 直接从主进程执行
- 备选：`session.webRequest.onHeadersReceived` 剥离 CSP 头

**Code Signing Inside-Out**：
```bash
# 正确顺序：先内层后外层
for fw in "$APP/Contents/Frameworks/"*.framework; do
  codesign --force --sign - --deep --preserve-metadata=entitlements "$fw"
done
for helper in "$APP/Contents/Frameworks/"*.app; do
  codesign --force --sign - --deep --preserve-metadata=entitlements "$helper"
done
codesign --force --sign - --preserve-metadata=entitlements "$APP"
```

**AgentSkin 可借鉴**：
- L4: CSP bypass 经验 → AgentSkin 的注入层文档可补充此知识
- L5: 外部 polling daemon 模式 → 参考其 superset-sidebar-highlight.js 的"外部进程通过 CDP 持续注入"模式
- L6: 127.0.0.1 vs localhost → macOS 上 IPv6 优先问题

**AgentSkin 不采纳**：
- asar patch（违反运行时注入原则）
- macOS 独占
- 仅 1 commit，工程成熟度极低

**使用方式**：
```typescript

// preload script
import { injectCSS } from "electron-css-injector"
window.addEventListener("DOMContentLoaded", () => {
   injectCSS("path/to/archive.css")

```

**技术原理**：
- 利用 Electron 的 `protocol` API 注册自定义协议
- 在 preload 阶段通过 `injectCSS()` 注入样式
- 不依赖外部 CDP 调试端口
- 应用启动时即注入，无运行时延迟

**与 AgentSkin 的对比**：

| 维度 | electron-css-injector | AgentSkin |
|------|----------------------|-----------|
| 注入位置 | 应用内 preload | 外部 CDP |
| 依赖 | 修改应用构建 | 零修改应用 |
| 稳定性 | 高（无端口依赖） | 中（依赖调试端口） |
| 适用场景 | 自建 Electron 应用 | 第三方 Electron 应用 |

**AgentSkin 可借鉴**：
- L7: 应用内注入思路 → AgentSkin 自身是 Electron 应用，可参考其 preload 注入模式优化自身 UI 主题
- L8: protocol API 注册 → 了解 Electron 底层 CSS 注入机制

**AgentSkin 不采纳**：
- 需要修改应用构建（AgentSkin 是注入器不是被注入应用）

**核心创新 — 零残留清理引擎 (purge-all.mjs)**：

```javascript
// 伪码：白名单式清理
const PURGE = {
  domIds: ['__CODEX_SKIN_CHROME__', '__CODEX_SKIN_SPARKLES__', ...],
  cssVars: ['--skin-primary', '--skin-glow', '--skin-accent', ...],
  timers: ['__skin_particle_timer__', '__skin_clock_timer__', ...],
  globalState: ['__skin_active__', '__skin_theme_name__', ...],
  homeClasses: ['codex-skin-home', ...]
};

function purgeAll() {
  // 1. 停止所有定时器
  PURGE.timers.forEach(t => clearInterval(globalThis[t]));
  // 2. 移除所有注入的 DOM
  PURGE.domIds.forEach(id => document.getElementById(id)?.remove());
  // 3. 清理 CSS 变量
  PURGE.cssVars.forEach(v => document.documentElement.style.removeProperty(v));
  // 4. 移除主页类名
  PURGE.homeClasses.forEach(c => document.body.classList.remove(c));
  // 5. 清理全局状态
  PURGE.globalState.forEach(s => delete globalThis[s]);
}
```

## 6. 推荐最优解与实施结果

### 方案 A：零残留清理引擎（P0 ✅ 已实施）

**来源**：ZhjGo/codex-skin-manager 的 purge-all.mjs 白名单式清理

**当前差距**：AgentSkin 的 theme 切换仅做 CSS 变量覆盖，不清理上一主题注入的 DOM 装饰元素、定时器、全局状态。切换主题后可能存在上一主题的残留粒子动画、装饰层等。

**执行建议**：
1. 新增 `scripts/lib/purge-engine.mjs` 模块
2. 定义清理契约：每个 bundle 声明其"注入痕迹"（DOM IDs、CSS 变量前缀、定时器 key、全局状态 key）
3. 主题切换时先执行 purge 再注入新主题
4. 清理契约与 14-token 契约并列，作为 bundle 的第二个不变量

**落地内容**：
1. 新增 `scripts/lib/purge-engine.mjs` — 白名单式清理引擎
2. 新增测试 `tests/main/purge-engine.test.ts`（15 个测试）

**测试结果**：15/15 ✅ passed

### 方案 B：自然语言主题意图解析器（P0 ✅ 已实施）

**来源**：xiongwenhao112/raccoon-dream-skin 的"一句话换肤"UX

**当前差距**：AgentSkin Studio 的操作依赖 GUI 点击，不支持自然语言驱动。用户无法表达"把主题换成蓝色系"或"投屏模式"等高层意图。

**执行建议**：
1. 新增 `scripts/lib/nl-theme-intent.mjs` 模块
2. 解析自然语言输入，映射到主题操作：
   - 颜色意图："蓝色系" / "暖色调" → 色相范围
   - 场景意图："投屏" / "护眼" / "夜间" → 预设配置
   - 强度意图："低调" / "浓郁" → 透明度参数
3. 输出结构化的 ThemeIntent，供 Studio 消费

**落地内容**：
1. 新增 `scripts/lib/nl-theme-intent.mjs` — 自然语言主题意图解析器
2. 新增测试 `tests/main/nl-theme-intent.test.ts`（12 个测试）

**测试结果**：12/12 ✅ passed
