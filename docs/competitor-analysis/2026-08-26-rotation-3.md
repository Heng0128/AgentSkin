## 2. 核心发现与行业趋势

### 趋势 1：语义化主题契约成为分水岭
`codex-styler` 的 `ThemeSemanticPalette` 定义了 19 个语义色角色（canvas/surfaceRaised/surfaceOverlay/control/borderSubtle/focus/success/warning/danger 等），主题作者完全不写 CSS、不碰目标应用选择器。这是目前最彻底的主题-应用解耦实现。

**对比**：AgentSkin 的 14-token 契约已接近这一水平，但 `control`/`focus`/`success` 等语义角色仍有缺失。

### 趋势 2：注入安全分层（Enhanced / Conservative）
`codex-styler` 将注入分为两级：
- **Enhanced 模式**：完整语义处理（导航/内容/Composer/对话框/线程摘要）
- **Conservative 模式**：仅背景 + 场景层

这是行业首次将"降级注入"作为一等公民，而非简单的 try-catch 回退。

### 趋势 3：运行时可交互实体（Companion 2.0）
从 Rotation 2 的静态 avatar-overlay，发展到 sprite-atlas + 方向感知 + 空闲动画序列 + 拖拽停靠的「Companion Studio」。6 个内置伙伴每个有独立的 pose-aware idle motion、direction smoothing、ground-line normalization。

### 趋势 4：CDP SDK 工具链成熟
`ntoskrnl7/electron-cdp` 展示了一个生产级 CDP 工具应有的全部能力：MainSession/Session 双层、自动 iframe/worker/sw 附着、SuperJSON 跨域序列化、执行上下文跟踪。这比直接用 `chrome-remote-interface` 更可靠。

### 趋势 5：热重载成为开发标配
`fishcold789` 的 PowerShell 注入脚本实现了 **250ms 文件变更检测 → 自动 CDP 重新注入**。开发者改 CSS 后 1/4 秒内即可在目标应用看到效果。

### 4.1 captainfod/TRAE-Work-Dream-Skin

**基本信息**

| 指标 | 数据 |
|------|------|

**技术实现**

1. **Shell 脚本编排的注入管道** — 全部逻辑使用 bash + macOS 原生工具（sips、osascript、launchctl），无需 Node 运行时
2. **应用签名验证** — `verified_cdp_endpoint()` 确保只注入官方签名的 TRAE Work 实例
3. **守护进程注入器** — `launch_injector_daemon()` 启动后台 Node injector，配合 `--watch` 参数监听主题目录变更
4. **状态持久化** — `~/.trae/` 目录记录 PORT / INJECTOR_PID / TRAE_PID / INJECTOR_STARTED_AT，重启时恢复
5. **内置 5 套预设** — Arcade Modern / Pixel 8-Bit / Electric Forest / Sky Friends / Retro 2007

**可移植给 AgentSkin 的部分**：
- 应用签名/路径验证的概念（AgentSkin 已有 environmentStore 类似能力）
- 图片处理管道：`sips -s format jpeg -s formatOptions 84 -Z 3200` 自动缩放 + 质量压缩至 16MB 以内
- 注入验证+守护进程重启模式

**不可移植**：全部 AppleScript/Shell 胶水代码是 macOS 专属。

### 4.2 xuhuanstudio/codex-styler

**基本信息**

| 指标 | 数据 |
|------|------|
| Stars | 14 |
| Forks | 1 |
| 语言 | TypeScript + Rust (Tauri) |
| License | Apache-2.0 |
| 当前版本 | v0.2.0-beta.9 (8/9) |
| **活跃提交** | 8/20（修复 multi-page CDP targets beta.9） |
| 平台 | macOS / Windows |

**架构亮点（核心）**

#### 四层边界隔离

```
apps/desktop          → Desktop Manager（React + Tauri shell）
packages/theme-core   → Theme Engine（schema + validation + 内置主题）
[internal]            → Versioned Codex Adapter（兼容性逻辑）
[runtime injected]    → Injected Scene Runtime（运行时注入器）
```

关键设计：**主题包从不包含 Codex 选择器**，所有兼容性敏感行为封装在 adapter 层。

#### 主题语义化契约（`packages/theme-core/src/types.ts`）

```typescript
export interface ThemeSemanticPalette {
  canvas?: string;
  surfaceRaised?: string;
  surfaceOverlay?: string;
  surfaceSunken?: string;
  control?: string;
  controlHover?: string;
  controlActive?: string;
  textTertiary?: string;
  onAccent?: string;
  borderSubtle?: string;
  borderStrong?: string;
  focus?: string;
  success?: string;
  warning?: string;
  danger?: string;
  info?: string;
  added?: string;
  modified?: string;
  deleted?: string;
}
```

19 个语义角色完全解耦于 Codex DOM。`ThemeAppearance` 定义 accent/surface/text/border 等基础色 + layout/iconStyle/decorations。`SceneLayer[]` 声明图像/渐变/暗角叠加层。`SceneEntity[]` 声明 renderer + behaviors + attachment。

#### 安全注入模型

```
1. 随机端口绑定 127.0.0.1
2. 启动 Codex with --remote-debugging-port=<PORT>
3. 验证 page target
4. 注入：1 幂等 scene root + 1 style node
5. 恢复：移除两个节点
```

- **Enhanced 模式**：完整语义处理 → live anchor 校验 → 计算样式比对 → 版本不符时 info 提示，仅实际问题触发降级
- **Conservative 模式**：仅背景 + 场景层，不碰导航/Composer

#### Composer Interactions（独特创新）

5 个 mini-game 替代 Codex 原生设置控件（Triple Drop / Capsule Crane / Loadout Forge / Three-axis Console / Mission Map），决定 model + reasoning + speed 三项设置。每局显示完整配置 → 确认 → 写入 → 读回验证。

> AgentSkin 定位不涵盖此功能，仅作为 UX 创新参考。

#### 主题包格式

```
.codex-styler-theme (ZIP)
├── theme.json          // ThemeDefinition
├── LICENSES.json
├── assets/*.{png,jpg,webp}
└── previews/*.{png,jpg,webp}
```

格式标识：`codex-styler-theme-v1`。JSON Schema + TypeScript interface 在 `packages/theme-core`。

**对 AgentSkin 的最大启示**：
- 19 语义色 > 14 token，说明 AgentSkin 还有语义细化的空间
- 「Enhanced/Conservative 双模式」是处理目标应用版本差异的最佳实践
- 主题包与适配层的彻底分离值得 RFC 评估

### 4.3 fishcold789/Taffy-Codex-Theme-Studio

**基本信息**

| 指标 | 数据 |
|------|------|
| Stars | 6 |
| Forks | 1 |
| 语言 | JavaScript + CSS |
| 最后提交 | 2026-07-28 (v2.3.4) |
| 平台 | Windows (PowerShell) |
| 目标应用 | Codex Desktop (Microsoft Store) |

**CSS 材质系统（本轮最深技术点）**

#### 1. 亚克力（Acrylic）— Fluent 雾化玻璃

实现原理三部曲：
- SVG fractalNoise 噪点纹理（`feTurbulence baseFrequency='0.85'` + `feColorMatrix saturate=0` + `feFuncA slope=0.085`）
- `backdrop-filter: blur() ` + 半透明底色叠加
- 斜向微光线性渐变（`linear-gradient` overlay）

CSS 变量 `--dream-acrylic-noise` 内联 SVG data URL，运行时通过 `:root.codex-dream-skin` 类切换。

#### 2. 液态玻璃（Liquid Glass）七项可调

- 边缘宽度
- 背景折射强度
- 高光（specular）强度
- 暗边（shadow edge）深度
- 光源方向
- 色散（chromatic aberration）
- 模糊度

通过纯 CSS `box-shadow` 多层 + `backdrop-filter` 组合模拟，无需 WebGL。

#### 3. DOM 装饰层注入

```
#codex-dream-skin-chrome  (position: fixed, z-index: 31, pointer-events: none)
  ├── .dream-brand         (左上 Logo + 主题名)
  ├── .dream-signature     (右上艺术签名，italic segoe script)
  ├── .dream-sparkles      (6 颗星光动画，十字光线)
  ├── .dream-polaroid      (右下相框，--dream-frame-art 变量)
  └── 星光、时钟、相框可拖动并记忆位置
```

装饰层在 `home-shell` class 出现时才显示（首页状态），任务界面自动隐藏——这与 Rotation 2 的「氛围自适应」思路一致。

#### 4. 热重载

```powershell
powershell -File .\runtime\scripts\hot-reload-taffy-skin.ps1
```

前台 watcher，`runtime/assets` 下 CSS/JS/图片任一保存后 ≈250ms 内自动重新注入。Ctrl+C 停止后皮肤保持。

**可移植给 AgentSkin**：
- ✅ CSS 材质预设（acrylic.glass 效果映射到 14 token 的 surface/overlay 变量）
- ✅ 250ms 文件监视 + CDP 重新注入工具
- ✅ 「装饰层仅在首页显示，任务页隐藏」的上下文感知注入策略

**不可移植**：
- ❌ PowerShell 专属脚本（AgentSkin 已有 Node 注入管道）
- ❌ 装饰层 Codex DOM 选择器

### 4.4 ntoskrnl7/electron-cdp

**基本信息**

| 指标 | 数据 |
|------|------|
| Stars | 2 |
| 包名 | `electron-cdp-utils` |
| 版本 | v0.4.9 |
| 最后提交 | 2026-05-18 |
| 语言 | TypeScript (dual ESM/CJS) |
| 依赖 | `devtools-protocol@0.0.1629771` + `superjson@2.2.6` + `electron@42` |

**架构**

#### 双层 Session

```typescript
// Base Session — 单一 CDP 通信链路
class Session {
  send(method, params?)     // 发送 CDP 命令
  evaluate(fn, args?, opts?) // 在目标执行 JS
  exposeFunction(name, fn, opts?) // 暴露 Node 函数到浏览器
  on(event, listener)       // 类型安全的事件监听
  executionContexts: Map<id, ExecutionContext>
}

// MainSession — 带 setup(）配置的入口
class MainSession extends Session {
  setup({
    preloadSuperJSON,           // 注入 SuperJSON 序列化器
    trackExecutionContexts,     // 跟踪 iframe/worker 上下文
    autoAttachToRelatedTargets  // 自动附加 iframe/worker/sw
  })
}
```

#### 关键能力

| 能力 | 说明 |
|------|------|
| **SuperJSON 跨域** | Date/Map/Set/Error/Buffer 自动序列化穿越 CDP |
| **自动附着** | iframe/worker/service_worker 出现时自动建立 session |
| **FrameId 类型** | `${processId}-${routingId}` 稳定标识 |
| **Service Worker 事件** | `service-worker-restarted` / `service-worker-version-updated` |
| **暴露函数字段** | `mode: 'CDP'` + `retry: { count, delay }` + `initScript` |
| **Setup 注入脚本** | `setup({ initScript })` 为每个执行上下文注入初始化代码 |

**对 AgentSkin 的启示**：
- 多窗口 Agent（如豆包多 WebView）需要管理多个 CDP Session，当前 engines/ 层是直接 WebSocket 连接——可考虑 Session Manager 封装
- SuperJSON 可解决当前注入器与渲染进程间的复杂数据交换（如传递结构化 token 对象）
- Electron 42 compatibility 表明其跟进最新的 CDP 协议版本

### 4.5 tluyben/electron-inject

| 最后提交 | 2025-03-15（已停滞 17 个月） |

**架构**

```
server.js  (Express HTTP server :3000)
  ├── POST /inject         { script }     → Runtime.evaluate
  ├── POST /dom            { selector }   → DOM.querySelector
  ├── POST /screenshot                  → Page.captureScreenshot
  ├── GET  /targets                     → /json (CDP TargetDiscovery)

```

命令行参数：`--port` (CDP 端口，默认 9222)、`--script` (预加载脚本)、`--server-port` (HTTP 端口)。

**技术价值**：
- DevTools 协议的标准 REST 化封装范本

- 查找策略优先级清晰，适合做 DOM 选择器健壮性研究

**局限性**：
- 完全停滞，依赖旧版 `chrome-remote-interface`
- 无多 page target 支持（单页假设）
- 仅作学习参考，无直接移植价值
