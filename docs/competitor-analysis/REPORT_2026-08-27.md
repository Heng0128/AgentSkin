## 二、逐项目深度分析

### 2.1 CodeDrobe/core — 统一换肤运行时

**基本信息**
- 仓库：https://github.com/CodeDrobe/core
- Stars: 9 | Forks: 2 | License: Apache-2.0
- 语言：JavaScript
- 创建：2026-07-16 | 最后更新：2026-08-05 | 最后提交：2026-07-21
- 版本历史：v0.1.1 → v0.7.0-beta.0（1 个月 7 个版本）

**支持的应用**
- Codex（macOS/Windows）
- WorkBuddy（macOS/Windows）
- QoderWork（CN + global，macOS/Windows）
- TRAE SOLO（global + CN，macOS/Windows）

**技术架构亮点**

1. **适配器模式（Adapter Pattern）**
   - 每个应用有独立的适配器定义（`getAdapter("codex")`）
   - 适配器包含：CDP 端口、probe markers、runtime keys、install paths
   - 适配器只定义稳定的跨路线 landmarks

2. **完整注入流程**
   - DOM preflight → 注入 → 验证 → 回滚
   - `applySkin()` 协调 host settings、launch、DOM preflight、renderer injection、verification、rollback
   - `watchTheme()` 接受 `AbortSignal`，Electron 主进程可自主管理生命周期

3. **按窗口兼容性判定**
   - 每个渲染窗口独立判定兼容性
   - 缺少 required landmarks 的次级窗口降级为 `"skipped": true`
   - 只有零个窗口合格时才失败

4. **DevToolsActivePort 发现**
   - QoderWork 强制 `remote-debugging-port=0`，调用者选择的端口永远不绑定
   - Core 自动从 `DevToolsActivePort` 文件读取实时端口
   - 显式 `--port` 永远优先

5. **DOM Snapshot API**
   - 只读 DOM + computed-style 快照，用于 AI 辅助主题创作
   - 记录：活跃主题、元素关系、语义类、稳定选择器候选、边界框、landmark 匹配、computed styles
   - 排除：文本内容、表单值、可访问名称、query/hash 数据、链接、媒体源

6. **商店发布系统**
   - `theme publish` 上传包到商店
   - `theme search` / `theme download` 匿名目录搜索和完整性验证下载
   - JSON Schema 验证 theme.json

**可借鉴的设计模式**

| 模式 | 描述 | 可行性 | 优先级 |
|------|------|--------|--------|
| 按窗口兼容性判定 | 多窗口场景下独立判定每个窗口 | 高 — 可改善 AgentSkin 的多窗口处理 | P1 |
| DevToolsActivePort 发现 | 自动发现 CDP 端口 | 高 — AgentSkin 已有类似机制，可参考边界处理 | P2 |
| DOM Snapshot API | 只读 DOM 快照供 AI 分析 | 中 — 需要额外实现，但价值高 | P2 |
| 声明式 landmarks | required/recommended/contexts 分层 | 高 — 可优化 AgentSkin 的验证逻辑 | P1 |
| 主题包转换 | 旧格式自动转换 | 低 — AgentSkin 无历史包袱 | P3 |

### 2.4 Lumos-789/zcode-cdp — ZCode CDP 协议层

**基本信息**
- 仓库：https://github.com/Lumos-789/zcode-cdp
- Stars: 1 | Forks: 0 | License: MIT
- 语言：JavaScript
- 创建：2026-08-01 | 最后更新：2026-08-15 | 最后提交：2026-08-15
- 版本历史：v0.2.0（2026-08-14 发布）

**技术架构亮点**

1. **Relay 架构（v0.2.0 核心变更）**
   - 无状态 TCP 中继（backend endpoint 永远有效）
   - 无 upstream 挂起（带超时）
   - attach 接通 / detach 断管道
   - 挂起语义天然替代应用层请求缓冲

2. **状态机简化**
   - 9 态 → IDLE/ENSURING/ACTIVE/CLOSING
   - 删除 synthetic initialize/activationBatch/generation fencing/restartPlaceholder
   - backend 从生到死只 spawn 一次（激活循环零重启）

3. **CLOSING 过渡态**
   - close 释放窗口内的 browser_close 直接成功
   - 防误自动重新激活
   - teardown 完成时有挂起连接自动重新 ensure

4. **标准回测体系**
   - L0 静态契约 marker（13 项）
   - L1 租约单元（12 项）
   - L1.5 relay 单测（8 场景）
   - L2 状态机端到端（11 项，stub backend/takeover）
   - 总计 44 项测试

5. **端口租约管理**
   - 启动前从日常 profile 同步扩展工具栏 pin 状态
   - Chrome 在拷贝的 user-data-dir 中会重置 extensions.pinned_extensions
   - 每次启动前从源 profile 恢复 pin 列表

6. **三层看门狗**
   - 限流/inBuf/启动去重/orphan 心跳/EPIPE 教训
   - stdout 限流改丢弃+告警（大 snapshot 合法，不杀唯一 backend）

**可借鉴的设计模式**

| 模式 | 描述 | 可行性 | 优先级 |
|------|------|--------|--------|
| CLOSING 过渡态 | 防止 close 后误激活 | 高 — 可改善 AgentSkin 的 CDP 连接管理 | P1 |
| 标准回测体系 | 分层测试（L0/L1/L2） | 高 — 可参考建立 AgentSkin 的 CDP 层测试规范 | P1 |
| 端口租约管理 | 进程级端口占用管理 | 中 — AgentSkin 已有 epoch-manager，可参考补充 | P2 |
| 状态机简化 | 减少状态数量，明确转换 | 高 — 可优化 AgentSkin 的注入状态机 | P1 |

## 四、推荐最优解方案

### 4.1 P0 — 立即执行（高价值 + 高可行性）

**方案 A：CDP 连接管理增强**
- 来源：zcode-cdp v0.2.0 的 CLOSING 过渡态
- 目标：改善 AgentSkin 的 CDP 连接生命周期管理
- 实施：在注入引擎中引入 CLOSING 状态，防止 close 后误激活
- 预期收益：减少 CDP 连接泄漏和误激活问题

**方案 B：声明式 landmarks 验证**
- 来源：CodeDrobe/core 的 required/recommended/contexts 分层
- 目标：优化 AgentSkin 的主题验证逻辑
- 实施：将现有验证逻辑重构为声明式 landmarks
- 预期收益：更灵活的验证配置，减少误报

### 4.2 P1 — 短期规划（高价值 + 中等可行性）

**方案 C：按窗口兼容性判定**
- 来源：CodeDrobe/core 的 per-window probe/verify
- 目标：多窗口场景下独立判定每个窗口
- 实施：修改 probe/apply/verify 流程支持多窗口
- 预期收益：改善多窗口用户体验

**方案 D：CDP 层测试规范**
- 来源：zcode-cdp 的 L0/L1/L2 分层回测体系
- 目标：建立 AgentSkin 的 CDP 层测试规范
- 实施：为 engines/ 目录下的 CDP 注入代码添加分层测试
- 预期收益：提高注入层可靠性

### 4.3 P2 — 中期规划（中等价值）

**方案 E：DOM Snapshot API**
- 来源：CodeDrobe/core 的 `codedrobe dom snapshot`
- 目标：提供只读 DOM 快照供 AI 辅助分析
- 实施：新增 `snapshotDom()` API
- 预期收益：支持 AI 辅助主题创作和问题诊断

**方案 F：DevToolsActivePort 边界处理增强**
- 来源：CodeDrobe/core 的 `resolveDebugPort(s)`
- 目标：完善 AgentSkin 的 CDP 端口发现机制
- 实施：增强端口发现逻辑，处理 `remote-debugging-port=0` 场景
- 预期收益：提高端口发现成功率
