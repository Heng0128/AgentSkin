## 1. CodeDrobe/core — 统一换肤运行时

### 1.1 核心架构

CodeDrobe 是一个**统一换肤运行时**，提供 CLI 和 ES Module 两种消费方式。核心设计：

```
用户 → CLI/SDK → applySkin() → 适配器(codex/workbuddy/qoderwork/traework) → CDP 注入
```

### 1.2 技术亮点

#### 1.2.1 适配器系统
- 内置 4 个适配器：`codex`, `workbuddy`, `qoderwork`, `traework`
- 每个适配器定义稳定的跨路由渲染器标记（landmark）
- 支持 `required`/`recommended`/`contexts` 三级验证
- 适配器文件限制为稳定跨路由标记，特性/主题相关 DOM 依赖放入主题目标

#### 1.2.2 DOM 快照
```bash
codedrobe dom snapshot --app codex --output /absolute/codex-dom.json
```
- 记录活跃主题、元素关系、语义类、安全属性、稳定选择器候选、边界框、适配器标记匹配、主题相关计算样式
- 排除文本内容、表单值、可访问名称、查询/哈希数据、链接、媒体源
- 只读操作，不启动、重启或变异应用

#### 1.2.3 兼容性预检
```json
{
  "targets": {
    "workbuddy": {
      "css": "workbuddy.css",
      "verification": {
        "required": [{ "name": "chat-surface", "any": [".chat-container", ".wb-cb-chat"] }],
        "recommended": [{ "name": "conversation-list", "any": [".conversation-list"] }],
        "contexts": [...]
      }
    }
  }
}
```

#### 1.2.4 主题包格式
- 最多 32 张命名 PNG/JPEG/WebP/GIF 图片
- 最大 30 MB
- 打包后嵌入 `assets.images`
- 渲染器创建作用域 Blob URL，每张图片暴露一个 CSS 变量 `--codedrobe-image-<id>`

#### 1.2.5 一键恢复
```bash
codedrobe restore
```
- 恢复主机设置，即使 Codex/CDP 离线
- 备份路径兼容旧 Skill

### 1.3 可借鉴点

| 特性 | 可行性 | 优先级 | 说明 |
|------|--------|--------|------|
| DOM 快照 API | 高 | P1 | 可用于主题编辑器的智能推荐 |
| 兼容性预检 | 高 | P1 | 注入前验证目标应用 DOM 结构 |
| 主题包格式 | 中 | P2 | 标准化主题分发格式 |
| 适配器分级验证 | 高 | P1 | 防止注入失败导致主题失效 |

## 2. xxxhh336/dream-work-theme — 跨平台主题切换器

### 2.1 核心架构

Dream Work Theme 是一个**面向 Electron Work 类应用的跨平台主题管理器**，支持 20+ 应用。

```
应用注册表 → CDP 端口检测 → 注入 CSS + 右下角菜单 → 即时切换
```

### 2.2 技术亮点

#### 2.2.1 应用注册表
```typescript
// electron/manager/app-registry.ts
```
- 管理已安装应用列表
- 支持应用选择和主题功能
- 根据应用窗口自动检测当前应用

#### 2.2.2 多应用支持
支持的应用列表（与 AgentSkin 6 个应用高度重合）：
- WorkBuddy ✓
- TRAE Work ✓
- QoderWork ✓
- CatPaw ✓
- ZCode ✓
- 豆包 Desktop ✓
- 以及其他 14 个非目标应用

#### 2.2.3 CDP 端口自动检测
- 每个应用有首选端口（QoderWork 9345, 豆包 9349, AgentCode 9350 等）
- 首选端口被占用时自动选择空闲端口
- 通过 `DevToolsActivePort` 文件获取运行时端口

#### 2.2.4 右下角菜单
- 4 个格子的快速切换菜单
- 显示当前应用的主题列表
- 点击"应用主题"或从目标应用右下角菜单切换都会计数
- 菜单初始化时 HanaAgent renderer 自动重注
- watcher 自动重新注入

#### 2.2.5 豆包 Desktop 特殊处理
- 使用固定 CDP 端口 9349
- 主题仅运行时注入，不修改豆包安装目录
- 原生界面只有亮色模式
- 暗色主题会重绘侧边栏、搜索、历史对话、头部标题、首页建议、对话内容及输入框操作栏的 `dbx`/`s-color` 原生 CSS token

### 2.3 可借鉴点

| 特性 | 可行性 | 优先级 | 说明 |
|------|--------|--------|------|
| 应用注册表 | 高 | P1 | 统一管理 6 个目标应用 |
| CDP 端口自动检测 | 高 | P1 | 自动发现运行中的应用实例 |

## 3. Finderchangchang/codex-autoskin — 一张图自动换肤

### 3.1 核心架构

Codex AutoSkin 的核心理念：**一张图片 = 一个主题**，用户只需发送一张图片，Agent 自动完成换肤。

```
用户发图 → Agent 克隆仓库 → 自动提取调色板 → 生成 theme.json → CDP 注入
```

### 3.2 技术亮点

#### 3.2.1 自动调色板提取
- 从参考图片自动提取主色调
- 亮/暗色路由检测（根据图片表面亮度）
- 生成覆盖全部 UI 区域的 CSS 主题

#### 3.2.2 主题格式极简
```json
{
  "schemaVersion": 1,
  "id": "my-skin",
  "name": "My Skin",
  "hero": "hero.webp",
  "colors": {
    "accent": "#24C9D7",
    "secondary": "#EF8FD2",
    "surface": "#F7FBFF",
    "text": "#17344F"
  }
}
```
- 只需 `schemaVersion` + `id` + `name` + `hero` 四个必需字段
- 图片必须归属于主题文件夹
- 颜色和文案（`copy`）可版权保护

#### 3.2.3 双栈端口探测
- 同时探测 IPv4/IPv6 端口
- 崩溃去抖动 + 断路器机制
- 装饰器命中测试

#### 3.2.4 持久化守护
- Windows: Startup Watcher（重启后重新应用）
- macOS: LaunchAgent（不中断已打开的 Codex）

#### 3.2.5 AI 细化规范
- THEME-SPEC.md — 为 Agent 编写的完整规范
- 28 个颜色 token
- 四种艺术角色的裁剪工作流
- 亮/暗色决策树
- 验收检查清单
- Agent 可从中生成主题并自我验证

### 3.3 可借鉴点

| 特性 | 可行性 | 优先级 | 说明 |
|------|--------|--------|------|
| 自动调色板提取 | 高 | P0 | 降低用户创建主题门槛 |
| 主题格式极简 | 高 | P0 | 简化 14-token 契约，提供快速路径 |
| AI 细化规范 | 高 | P1 | 为 Agent 编写主题生成规范 |
| 双栈端口探测 | 中 | P2 | 提升连接稳定性 |
| 持久化守护 | 高 | P1 | 应用重启后自动恢复主题 |

- 应用主题后 WorkBuddy 右上角出现 ✨ 按钮

- 支持自定义图片上传（canvas 自动取色 + 压缩为 webp）
- 自定义主题行 ✨ 一键删除
- "原生界面"恢复官方外观

#### 4.2.2 自动取色
- 根据主题取色表面的 surface 亮度自动切换 WorkBuddy 的 `data-vscode-theme-kind`
- 让 VS Code 原生控件（输入框、按钮等）跟着深/浅色变化

#### 4.2.3 主题格式
```json
{
  "schemaVersion": 1,
  "id": "my-skin",
  "name": "My Skin",
  "hero": "hero.webp",
  "colors": {
    "accent": "#24C9D7",
    "secondary": "#EF8FD2",
    "surface": "#F7FBFF",
    "text": "#17344F"
  }
}
```

#### 4.2.4 内置主题
- 10 个内置主题：Miku Light, Miku 488137, Genshin Dawn, Genshin Night, Deepspace Dawn, Deepspace Star, Naruto Hokage, Naruto Sasuke, Wuthering Echo, Wuthering Tide
